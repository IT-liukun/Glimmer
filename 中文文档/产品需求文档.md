## 1. 这是做什么的

微光帮公益机构把钱的来龙去脉记清楚。

管理人员先记下「这个人对外是谁」，再记下每一笔钱。创建项目时必须指定受益人。然后把整笔善款挂到一个项目上，并记下开销。

三件事：

- 捐款人用手机号登录。身份上的手机号一致时，系统自动认领。也可以再手动绑定其他平台身份。
- 受益人登录后绑定唯一 ID。这样就能认出哪些项目包含自己。
- 项目、项目详情里的「善款」，以及善款捐赠明细，所有人都能看。敏感身份不进入公开页面。规则见第 6 节。

本期功能全部是 P0，不设 P1。验收见第 11 节，范围见第 12 节。

## 2. 谁在用，怎么走

同一个人可以既捐款又受助。用同一个手机号登录后，先认领捐款身份，再绑定一名受益人。

| 角色 | 怎么进入 | 主要事情 |
| --- | --- | --- |
| 管理人员 | 手机号已录入为管理员。先完成用户登录。「我的」出现「进入后台」。点击后进入项目列表 | 记账、立项、绑定善款、登记开销、维护受益人 |
| 捐款人 | 任意手机号。用密码或短信验证码 | 查看自己的善款去向。修改已认领身份的对外资料 |
| 受益人 | 同上。再绑定姓名和唯一 ID | 查看包含自己的项目，以及公开的捐款来源 |
| 未登录访客 | 不登录 | 查看公开的项目和善款明细 |

```text
预先录入管理员手机号 → 用户登录 → 「进入后台」→ 项目列表
        ↓
建立受益人 → 创建项目（必须带至少一名受益人）
        ↓
录入善款：生成或更新捐款身份，再新增善款
        ↓
整笔绑定到一个项目，并登记开销
        ↓
所有人查看公开页面
捐款人登录后认领身份；受益人登录后绑定唯一 ID
```

```text
平台 + 平台用户 ID → 一条捐款身份 → 多笔善款 → 善款上的项目 → 项目开销
一个登录手机号只有一条登录身份 → 多个捐款身份、一个受益人
受益人 → 至少一个 → 项目
```

金额在服务端用人民币计算。必须大于 0。最多两位小数。

```text
一笔善款最多挂在一个项目上。挂上的金额等于善款全额
项目善款合计 = 当前挂在该项目上的善款金额之和
项目开销合计 = 开销金额之和
项目结余 = 善款合计 - 开销合计
超支 = 结余 < 0
```

下面几条全篇通用：

- 一个手机号只有一条登录身份。上面可以有多个捐款身份，最多一个受益人。
- 同一捐款身份、同一受益人档案，可以同时出现在多个手机号的登录身份上。
- 从当前手机号拿掉捐款身份，或清空受益人，只改这一条登录身份。不删除捐款身份、受益人档案、善款和项目。
- 善款有没有挂项目，只看它的项目有没有值。公开项目详情只列出项目就是该项目的善款。
- 作废后的善款从善款列表和公开页面移出，只留在管理端「作废善款」，并且项目清空。
- 已删除的开销从公开页面和管理端项目详情都移出，开销合计减去这笔。

## 3. 登录与认领

全系统不设用户名，也不设注册。

登录默认用手机号和密码。也可以切换成短信验证码。重置密码用手机验证码。

验证码 5 分钟内有效。同一手机号 1 小时内最多发送 5 次。密码至少 8 位。登录过期后要重新登录。退出登录会清掉本机的登录状态。短信验证码不写入业务日志。

管理端和用户端分开。管理人员不在用户端改台账。捐款人和受益人不能进入管理端。

全系统只有一套登录，在用户端「我的」。没有单独的管理员登录。未登录时也没有管理员入口。

打开时停在密码登录。可以改用验证码登录。重置密码从这一页进去。输入框怎么摆，见《原型图描述文档》的「我的」未登录。

密码提示不是密码。这个号码留过提示时，登录页会把它显示在密码框旁边。留空则不显示。

### 3.1 管理员

记录只有姓名和手机号。没有状态。手机号在管理员中唯一。一开始至少有一名管理员。

新增就是新录入一条记录。不再使用时，直接删除这条记录。不改状态。管理端名单只读。

必须始终保留至少一名管理员。不能删到一名都不剩。

记录删除后，这个手机号仍可以用用户登录，但不能进入管理端。

手机号还在管理员记录里时，完成用户登录后，「我的」页头出现「进入后台」。还没录入，或记录已删除时，不出现这个按钮。点击后直接离开用户端，进入项目列表。

点击时如果记录已经删除，留在「我的」。页头不再显示「进入后台」，并提示「该手机号没有管理权限」。

管理端每次请求都核对当前登录手机号：登录还有效，并且这个手机号还在管理员记录里。未登录、未录入或记录已删除时，拒绝请求，不返回台账。

### 3.2 用户登录与自动认领

用户端手机号不需要预先录入。登录身份就是这个手机号的个人空间。一个手机号只有一条。认领的捐款身份和绑定的受益人都记在这一条上。不另建认领记录或绑定记录，也没有状态。

验证码登录第一次通过，就建立这条登录身份，并留在「我的」。

密码登录不建立登录身份。这个手机号还没有登录身份，或还没设置密码，或密码不对时，停在登录页。可以改用验证码登录，或对已有登录身份重置密码。

页头是否出现「进入后台」，见第 3.1 节。

两种方式登录成功后，系统都做同一件事：找出捐款身份上的手机号与这次登录手机号相同、并且还没记在这条登录身份上的身份，自动加进去。

自动加入只看手机号。不要求该身份已经有善款。同一次登录可以加上多条。已经在这条记录上的不重复添加。

这些身份出现在捐赠身份列表中。打开一条后，捐款列表展示该身份下还在的善款。

重置密码从登录页进入。填写手机号、短信验证码、新密码和确认新密码。也可以填写密码提示。提示不是必填。

重置只改已经存在的登录身份。还没有登录身份时，不能靠重置建立，要先用验证码登录。

验证码通过，并且两次密码一致后，写入新密码和密码提示，回到登录页。用新密码登录。留空则这个手机号不再保留密码提示。

验证码错误、过期，或两次密码不一致时，停在重置页。

没有匹配手机号的身份，按第 3.3 节手动绑定。受益人的「包含我」要等第 3.4 节绑定成功后才出现。

### 3.3 手动绑定捐款身份

捐款人填写「平台 + 平台用户 ID」。平台使用第 4 节的同一份清单。

平台用户 ID 去掉首尾空格后精确匹配。区分大小写。

该身份下至少有一笔还在善款列表里的善款，并且还没记在当前手机号这条登录身份上时，提交后就把该捐款身份加进去。不展示笔数和金额合计。也不再进入确认页。

没有匹配身份，或名下已经没有还在列表里的善款时，提示「未找到对应捐款记录」。这条登录身份不变。

一个手机号可以绑定多个身份。重复绑定提示已绑定。多个手机号可以绑定同一个身份。大家看到的是同一条身份及其善款。

解除后，从这一条登录身份上拿掉该捐款身份。这个手机号的捐赠身份列表和捐款列表不再显示这些善款。身份、其他手机号的记录、善款及其项目不受影响。

### 3.4 绑定受益人

提交姓名和唯一 ID。与档案去掉首尾空格后一致，就把该受益人写入当前手机号这一条登录身份。

绑定在「我的」的「我的受益」里展开和收起。不另开页面。

提交后表单收起。包含自己的项目列在这个标题下。受益人姓名和打码号码在项目列表上方。不再显示「绑定受益人身份」。

不一致或档案不存在时，统一提示「未找到匹配的受益人信息」。不说明是哪一项不对。

一个手机号同时只能绑定一个受益人档案。更换前先解除。多个手机号可以绑定同一个档案。

解除后，清空这一条登录身份上的受益人。这个手机号不再显示「包含我」。档案、项目和其他手机号记录上的受益人仍保留。

### 3.5 修改已认领身份，和管理人员更正

这是两件不同的事。已登录用户可以改自己的资料。第 9 节里管理人员那一列写「无」，只表示管理端不做这件事。

已登录用户在「我的」修改已认领身份。能改是否匿名、对外展示名、个人说明。不能改平台、平台用户 ID 和手机号。

保存上述任意一项后，身份标记为「用户已修改」，并记录修改时间。多个登录手机号认领同一身份时，任一手机号保存都会加上这个标记。

捐款人之后仍可以继续修改这三项。

管理人员在管理端的身份详情更正这三项。用户已经改过也可以。不必为此新增善款。管理人员保存后，标记改回「未修改」，修改时间清空。原先已是未修改的，保持未修改。

单笔录入不修改身份资料。

标记为「未修改」时，导入仍可以覆盖对外展示名。标记为「用户已修改」时，导入不再覆盖是否匿名、对外展示名、个人说明。

管理人员把标记改回未修改后，下一次导入重新按未修改处理。

手机号只随批量导入更新。不受「用户已修改」限制。覆盖范围见第 4.2 节。

## 4. 捐款身份与善款

身份回答「这个人对外是谁」。善款回答「这一笔钱是多少」。

身份键是「平台 + 平台用户 ID」。同一个键只有一条身份。

同一身份下的多笔善款，都显示该身份当前的对外资料。不在每笔善款上另存一份。

平台清单首期是微信支付、支付宝。以后追加时，录入、导入和手动绑定使用同一份清单。

### 4.1 字段

捐款身份和善款分开。

平台、平台用户 ID、是否匿名、对外展示名、个人说明、手机号属于捐款身份。金额、捐款日期、订单编号、备注属于善款。

捐款身份在「捐款身份」列表中创建。创建时填写身份字段，不产生善款。

| 字段 | 创建身份 | 批量导入 | 说明 |
| --- | --- | --- | --- |
| 平台 | 必填 | 必填 | 平台清单中的一项。创建后不能修改 |
| 平台用户 ID | 必填 | 必填 | 最长 64 个字符。与平台组成身份键。创建后不能修改 |
| 是否匿名 | 必填，默认「是」 | 不录入 | 导入新建时写「是」。导入永不修改此项。单笔录入不修改 |
| 对外展示名 | 选填 | 选填 | 未匿名时公开。为空时公开页面显示「{平台}捐款人」 |
| 个人说明 | 选填，不超过 200 字 | 不录入 | 用户端善款页和项目详情的善款不展示。导入新建时为空。导入永不修改。单笔录入不修改 |
| 手机号 | 选填 | 选填 | 11 位中国大陆手机号。捐款人不能修改。创建时可以填写。批量导入有值时更新，留空不改变。用户已修改也不阻止这次更新 |

| 字段 | 单笔录入 | 批量导入 | 说明 |
| --- | --- | --- | --- |
| 捐款身份 | 必填。查询后添加一条已有身份 | 按本行的平台和平台用户 ID 匹配。没有则创建 | 单笔录入不新建身份，也不修改身份资料。查询前不列出全部身份 |
| 金额 | 必填 | 必填 | 大于 0，最多两位小数 |
| 捐款日期 | 必填 | 必填 | 不得晚于录入当天 |
| 订单编号 | 必填 | 必填 | 最长 64 个字符，全库唯一。创建后不能修改。批量作废按它查找。不进入公开页面 |
| 备注 | 选填 | 不录入 | 仅管理人员可见。导入生成的备注为空。不作单独修改。作废后，原因写入作废记录的备注，原备注留在前面 |

### 4.2 创建身份、单笔录入与导入覆盖

管理端展示捐款身份列表，并可以创建捐款身份。

创建只写入身份字段。「用户已修改」为「未修改」。不产生善款。同一身份键已存在时不能再次创建。平台和平台用户 ID 创建后不能改。

单笔录入按平台用户 ID、手机号或对外展示名查询已有捐款身份。从结果中添加一条。再填写金额、捐款日期、订单编号和备注。

查询前和空条件都不列出全部身份。查询结果和已选身份展示完整手机号，不打码。

本页不出现这些填写项：平台、平台用户 ID、是否匿名、对外展示名、个人说明、手机号。桌面和移动怎么排，见《原型图描述文档》「单笔录入」。

没有匹配的身份时不能保存。先去创建。

保存后只新增一条尚未安排到项目的善款，挂在所选身份下。身份资料保持不变。

管理人员更正身份资料的规则见第 3.5 节。单笔录入不进入那条规则。

批量导入使用 Excel（`.xlsx`）。

列：平台、平台用户 ID、对外展示名、手机号、金额、捐款日期、订单编号。不包含是否匿名、个人说明、备注。

只读第一个工作表。第一行是表头。平台用户 ID、手机号、订单编号按文本读取。页面提供模板下载。模板见第 13 节。

整批成功后，原文件存入导入目录。任一行失败则整批不写入，也不保存文件。

导入前先预览并标错。

- 身份未修改时，标明展示名将更新。手机号将写入，或因留空不改变。
- 身份已修改时，标明展示名本次不覆盖。手机号有值仍标明将写入。留空仍标明不改变。

全部行通过后，按从上到下一次写入。任一行失败则整批不写入，并返回行号和原因。单次最多 500 行。

每一行按这个顺序处理：

1. 身份不存在就创建。匿名为「是」。个人说明为空。「用户已修改」为「未修改」。展示名用本行内容。手机号有值则写入。
2. 身份已存在，且用户未修改：用本行展示名覆盖。空值也覆盖。不改匿名和个人说明。手机号有值则更新。留空不改变原手机号。
3. 身份已存在，且用户已修改：不改匿名、展示名、个人说明。手机号有值则更新。留空不改变原手机号。
4. 新增一条尚未安排到项目的善款，挂在本行身份下。写入本行订单编号。备注为空。

同一身份在一批中出现多行时，每行各生成一笔善款。用户未修改时，展示名以最后一行为准。

手机号不论用户是否已修改，都以本批最后一条非空手机号为准。全部留空则不改变。

导入写入或更新手机号后：这个号码已经有登录身份，就把该捐款身份加进这一条。否则下次登录再加。已经在记录上的保留。

这次没有改手机号，就不会自动加回去。捐款人先前从自己的登录身份上拿掉了该身份，只要导入没有写入或更改手机号，它就继续留在外面。

捐款人不能自己改手机号。

校验：

- 平台在清单内
- 平台用户 ID 非空，且不超过 64 个字符
- 手机号为空，或为 11 位中国大陆手机号
- 金额大于 0，且最多两位小数
- 日期为 `YYYY-MM-DD`，且不晚于当天
- 订单编号非空、不超过 64 个字符，且在本批和已有善款中都不重复

举例：

1. 先创建一条捐款身份。匿名为「是」。这时还没有善款。
2. 单笔录入查询并添加它。只新增一笔尚未安排到项目的善款。身份仍是匿名。
3. 用户还没修改时，在身份详情改为不匿名。展示名「张三」。个人说明「希望用于助学」。不新增善款。标记仍是未修改。
4. 用户随后把展示名改成「张先生」。标记变为用户已修改。
5. 之后单笔录入仍然只新增善款。导入不再覆盖展示名。
6. 捐款人不能改手机号。导入行如果带了手机号，身份手机号仍更新为该值。留空则保持原手机号。
7. 管理人员再次更正展示名后，标记改回未修改，修改时间清空。之后导入又可以覆盖展示名。

### 4.3 管理端列表、更正与作废

捐款身份列表按平台、平台用户 ID、手机号查询并分页。从这里创建身份，或打开身份详情。还没有善款的身份也留在列表中。每一行有哪些字，见《原型图描述文档》「捐款身份列表」。

善款没有状态字段。有没有挂到项目，只看它的项目有没有值。列表可以按「全部 / 已安排 / 尚未安排」筛选。

善款列表默认按捐款日期倒序，并分页。可以查订单编号、捐款身份平台 ID、捐款身份姓名或手机号、是否已安排到项目，以及捐款日期起止。列、卡片和折叠见《原型图描述文档》「善款列表」。

捐款身份姓名读所属身份现在的公开称呼，不保留录入那一刻的旧副本。项目为空就是尚未安排。没有备注时按「无」理解。页面上具体怎么写，见《原型图描述文档》。

管理端没有善款详情页。身份详情展示身份字段、手机号、修改标记、修改时间，以及名下善款。名下善款不能再打开某一笔。公开列表的字段见第 6 节。

善款不能改金额和日期。金额或日期有误时，作废这笔，再重新导入。

善款不能改挂到另一个身份。身份键录错时，不能改原身份的平台和平台用户 ID。要另建正确身份，再作废这笔，选取正确身份重新单笔录入。

作废后，这条善款从善款列表、公开页面、身份名下和可绑定名单移出，记入「作废善款」。不再挂在任何项目上。原先挂着的，项目合计减去这笔。

作废时间取确认当时。作废原因写入这条作废记录的备注。原来有备注的，留在前面，后面接「作废原因：……」。

还在善款列表里的都可以作废，不论当时有没有挂到项目。必须填写原因。确认页先展示这笔当前的项目。确认之后，作废记录不再挂项目。

身份下善款全部作废后，身份仍保留。此后不能按第 3.3 节手动绑定。手机号仍匹配时，第 3.2 节的自动加入仍然生效。

「作废善款」在「导入文档」后面。列出已经作废的善款。默认按作废时间从新到旧，并分页。查询条件与善款列表相同的有：订单编号、捐款身份平台 ID、捐款身份姓名或手机号、捐款日期起止。不按项目查询。作废日期起、作废日期止和捐款日期一起收在折叠查询里。列、卡片和折叠见《原型图描述文档》「作废的善款」。

批量作废与批量导入走同一条路：下载 Excel 模板、上传 `.xlsx`、预览、全部通过后确认写入。

列是订单编号、作废原因。订单编号按文本读取。按订单编号找到已有善款。

预览标明将记入「作废善款」，并且不再挂项目。挂在项目上的，标明项目合计减去这笔。原因写入该条备注，也留在这份 Excel 里。作废时间取确认写入当时。

这些情况都算该行失败：订单编号为空、订单编号不存在、本批订单编号重复、原因为空。

任一行失败则整批不写入，不保存文件，并返回行号和原因。全部通过后，原文件存入作废目录。这些善款记入「作废善款」。

导入目录和作废目录分开。都在「导入文档」页提供下载。单次最多 500 行。超过时不逐行写入。模板见第 13 节。

编号：善款 `SK` + 年月日 + 4 位当日流水。

## 5. 项目、受益人、绑定与开销

### 5.1 受益人档案

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 姓名 | 是 | 管理人员可见。绑定成功的受益人本人可见自己的姓名 |
| 唯一 ID | 是 | 推荐身份证号。档案内唯一。加密存储 |
| 备注 | 否 | 仅管理人员可见 |
| 更新日期 | 系统写入 | 最近一次保存档案的日期。新建项目的「添加受益人」和追加受益人，都按它从新到旧分页。只含尚未加入本项目的档案。每页几条、卡片怎么排，见《原型图描述文档》 |

列表和详情里，唯一 ID 默认只留前 3 位和后 4 位。点击后看完整号码。受益人列表按姓名、唯一 ID 查询并分页。一名受益人可以加入多个项目。

### 5.2 创建项目与状态

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 项目名称 | 是 | 不超过 50 字 |
| 项目简介 | 是 | 公开 |
| 开始日期 | 是 | |
| 受益人 | 是 | 至少一名。先点「添加受益人」再从尚未加入本项目的档案里选。可添加多名。怎么展开、怎么分页，见《原型图描述文档》「新建项目」 |

未添加受益人不能保存。提示「请至少选择一名受益人」。

入口有两处：项目列表的「新建项目」；受益人详情的「创建项目」。

从受益人详情进入时，当前受益人已经添加，且不能移除。其他人在展开「添加受益人」后，按更新日期倒序分页。

追加受益人只在进行中的项目上可用。名单里只出现还没加入本项目的档案，按更新日期倒序分页。

两处都按更新时间从新到旧分页。桌面默认每页 10 条。移动每页固定 5 条。也可按姓名或唯一 ID 查询。卡片怎么排，见《原型图描述文档》。

已完成或已关闭不能追加。要先改回进行中。已经加入本项目的人不提供添加。

创建后为「进行中」。善款合计、开销合计、结余都是 0。项目没有封面。

只有进行中可以修改名称、简介、开始日期。已完成、已关闭要先改回进行中。

项目不能删除。管理端项目列表不提供「删除」。进行中、已完成、已关闭都留在列表里。

| 状态 | 含义 | 可以做 | 不能做 |
| --- | --- | --- | --- |
| 进行中 | 正在执行 | 编辑项目、标记完成、标记关闭、追加受益人、移除受益人、发布进展、编辑已有进展、删除已有进展、绑定善款、解除善款、登记开销、编辑开销、删除开销 | 删除项目 |
| 已完成 | 活动结束 | 改回进行中、绑定善款、解除善款、登记开销、编辑开销、删除开销、编辑已有进展、删除已有进展 | 编辑项目、追加受益人、移除受益人、新增进展、删除项目 |
| 已关闭 | 暂停 | 与已完成相同 | 与已完成相同 |

移除受益人只在进行中。已完成或已关闭要先改回进行中。移除后至少保留一名受益人。只剩一名时提示「项目至少保留一名受益人」。

项目和受益人的关系记在「受益人项目关联」上。没有状态。加入就是新增一条。移除就是删除这条。

已经有关联的不重复新增。删掉之后再加入，是新的一条。

受益人还没登录时，关联仍然算数。绑定成功后就能看到「包含我」。

项目详情一次列出当前关联的全部受益人，展示备注，不查询、不分页。进展、善款、开销怎么折叠、图片怎么翻，见《原型图描述文档》「项目详情」和「详情里记录太多时」。

删除进展后，管理端和公开页面都不再展示该条。

编号：项目 `XM` + 年月日 + 4 位当日流水。

### 5.3 善款绑定

管理人员从项目详情，把一笔尚未安排的善款挂到任意状态的项目。不填写金额。挂上的是全额。

尚未安排的善款，按捐款日期从新到旧分页后确认。也可按订单编号、善款编号或平台用户 ID 查询。空条件仍是这份名单。每页几条见《原型图描述文档》「选择尚未安排的善款」。

保存后，这笔挂到该项目上。项目善款合计和结余重算。

已经挂在项目上的善款不能再挂到别的项目。要换项目，先解除再挂。同时有两个人操作时，只有一个请求成功。后到的提示这笔已经挂在项目上。

解除不填原因。清空这笔善款的项目，项目善款合计减去全额。善款记录还在。公开项目详情只显示项目仍是该项目的善款。

尚未安排的善款，在捐款列表和善款捐赠明细中，显示「尚未安排到具体项目」。

### 5.4 开销

进行中、已完成、已关闭都可以登记。开销不改写善款，也不分摊到某一笔善款。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 开销日期 | 是 | 不得晚于录入当天 |
| 类别 | 是 | 物资采购、交通食宿、人员补贴、其他 |
| 金额 | 是 | 大于 0，最多两位小数 |
| 说明 | 是 | 公开 |

保存后重算开销合计和结余。开销可以大于善款。这时标记「超支」，并且仍然保存。

开销没有状态。管理端项目详情可以编辑日期、类别、金额、说明，也可以删除。删除后管理端和公开页面都不再展示，开销合计减去这笔。不填写删除原因。

开销在项目详情中按日期倒序。编号：`KX` + 年月日 + 4 位当日流水。

### 5.5 项目进展

只有进行中的项目可以发布。一条进展包含日期、标题、正文、图片。按时间倒序出现在公开项目详情。

已有进展可以编辑，也可以删除。删除后，管理端和公开页面都不再展示。

已完成和已关闭不能新增。已发布的仍可以编辑或删除。

编号：`JZ` + 年月日 + 4 位当日流水。

## 6. 谁能看到什么

传输使用 HTTPS。手机号、平台用户 ID、受益人唯一 ID 是敏感信息。

页面上，手机号和唯一 ID 默认保留前 3 位和后 4 位。管理端台账展示完整平台用户 ID。身份手机号和受益人唯一 ID 点击后再看完整值。单笔录入的查询结果和已选身份展示完整手机号，不打码。见第 4.2 节。

### 6.1 不用登录也能看

未登录可以打开项目列表、项目详情和善款捐赠明细。各页字段、查询、空状态和卡片见《原型图描述文档》。

项目列表不显示结余、项目编号和「超支」。默认按开始日期从新到旧。可以按项目名称、状态查询。卡片怎么排，见《原型图描述文档》。

结余小于 0 就是超支。用户端项目列表不显示超支。用户端项目详情显示。管理端项目列表和项目详情都显示。刚创建、善款和开销都还是 0 时，结余为 0，没有超支。

项目详情按进展、善款、开销排列。善款只含当前挂在本项目上的。开销只含还在的记录。折叠条数见原型图「详情里记录太多时」。

善款捐赠明细含全部善款。按捐款日期从新到旧。可以按是否已安排到项目筛选，选项为「全部」「已安排」「尚未安排」。不按平台查询。尚未安排的不能点进项目。

公开称呼：

- 匿名是「匿名捐款人」。不显示对外展示名。
- 未匿名是对外展示名。展示名为空时用「{平台}捐款人」。

用户端善款页和项目详情的善款都不展示个人说明。个人说明最长 200 字。

公开页面不展示：平台用户 ID、订单编号、身份手机号、善款备注、受益人姓名、唯一 ID、受益人备注、他人的「包含我」和「我的捐款」。已作废的善款、已删除的开销和已删除的进展不在公开页面。

### 6.2 登录后多看到的标记

认领了对应捐款身份的用户，在项目详情的「善款」里，自己的行上看到「我的捐款」。

「我的」上有哪些卡片和按钮，见《原型图描述文档》。下面只写登录后多出来的含义。

身份已经逐条列在页面上。不再单独统计已认领身份数。也不按平台筛选。

金额汇总只统计还在善款列表里、并且记在这条登录身份上的善款。作废的不计入。

- 累计捐款金额 = 这些善款的金额之和
- 已进入项目的金额 = 其中项目有值的金额之和
- 尚未安排的金额 = 其中项目为空的金额之和

三者满足：累计捐款金额 = 已进入项目的金额 + 尚未安排的金额。没有任何认领时，三项都是 0，页面给出手动绑定入口。

绑定捐赠身份在「我的」本页展开。提交后仍留在「我的」。打开一条身份，进入该身份的捐款列表。每笔只显示金额、是否已安排、时间和项目。不展示管理备注和平台用户 ID。

解除绑定先弹出确认。确认后才解除。取消则不解除。

绑定受益人后，包含自己的项目直接列在「我的受益」下。不另写「受益项目」。不另开页面。也不按名称或状态筛选。没有时说明「暂时没有包含我的项目」。打开一条后，项目详情显示「包含我」。

未绑定时只说明绑定后才会列出项目，不展示项目。绑定成功后不再显示「绑定受益人身份」。这些空状态不代替公开列表。

登录手机号还在管理员记录里时，「我的」才出现「进入后台」。

### 6.3 只有管理人员能看

全部台账、善款备注、身份手机号、受益人名单和完整唯一 ID。

管理端这些列表的表格、卡片和查询见《原型图描述文档》。

## 7. 页面从哪进

各页面上有什么，见《原型图描述文档》。点完走到哪，见《用户用例手册》。

管理端和用户端打开后都先是项目列表。顺序都是先项目，后善款。每次请求管理端，都核对当前登录手机号还在不在管理员记录里。规则见第 3.1 节。

不另设首页。尚未安排的善款在善款列表里筛选。进行中的项目、超支项目，在项目列表里筛选。

把已有记录加进另一条时，三种入口不一样：

- 单笔录入选捐款身份：查询前和空条件都不列出。见第 4.2 节。
- 添加受益人：展开后就按更新日期分页列出尚未加入本项目的档案。空条件也列出。见第 5.2 节。
- 选择尚未安排的善款：空条件就是这份分页名单。见第 5.3 节。

对象自己的列表页仍展示全部台账。分页条数见第 5.2 节和第 5.3 节。

公开页面有：全部项目、项目详情（含进展、善款、开销）、善款捐赠明细。底部是「项目」「善款」「我的」。

「我的」未登录时只有用户登录。登录并自动认领后，仍留在「我的」。手机号还在管理员记录里时，另有「进入后台」。

## 8. 数据对象

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |
| 管理员 | 姓名、手机号 | 手机号预先录入。没有状态。新增就是新录入一条。不再使用就删除这条记录 |
| 登录身份 | 手机号、密码、密码提示、最近登录时间、捐款身份、受益人 | 一个手机号只有一条。第一次用验证码登录通过后生成。捐款身份可以有多个，受益人最多一个。没有状态。认领是把捐款身份加进这条记录，解除是拿掉。绑定受益人是写入这一项，解除是清空。同一捐款身份、同一受益人可以出现在多个手机号的记录上。密码由用户设置，也可以用验证码重置。密码提示不是密码。重置时可以填，留空则不保留。登录页把它显示在密码框旁边 |
| 捐款身份 | 平台、平台用户 ID、是否匿名、对外展示名、个人说明、手机号、用户已修改、修改时间 | 身份键唯一。手机号用于登录时自动加入对应的登录身份 |
| 善款 | 编号、订单编号、身份 ID、金额、捐款日期、备注、项目 | 订单编号全库唯一。没有状态。项目有值时，这笔全额挂在该项目上。清空项目就是解除。作废后从善款列表移出，项目一并清空 |
| 作废善款 | 原善款字段、作废时间、备注 | 不挂项目。作废原因写在备注里，原备注留在前面。只在「作废善款」查看 |
| 项目 | 名称、简介、开始日期、状态、善款合计、开销合计、结余 | 至少一名受益人 |
| 项目开销 | 项目、日期、类别、金额、说明 | 没有状态。删除后不再计入开销合计 |
| 受益人 | 姓名、唯一 ID、备注、更新日期 | 唯一 ID 档案内唯一。更新日期由系统在保存档案时写入 |
| 受益人项目关联 | 受益人、项目 | 没有状态。加入项目就新增一条。移除就删除这条。同一受益人在同一项目上只有一条 |
| 项目进展 | 项目、日期、标题、正文、图片 | 只有进行中可以新增。已有的可以编辑和删除。删除后不再展示 |

捐款身份的唯一键是「平台 + 平台用户 ID」。善款、项目、开销、进展的编号规则见对应小节。

## 9. 权限

三列按入口区分，不按人互斥。同一个人可以既是管理人员，又是已登录用户。

管理人员列只表示管理端能不能做。已登录用户列只表示「我的」能不能做。管理人员打开「我的」时，按已登录用户列执行。所以下面「修改已认领身份」在管理人员列是「无」：管理端不做，本人在「我的」里可以做。

| 能力 | 管理人员 | 已登录用户 | 未登录访客 |

## 11. 验收

按下面的路径核对。每条只验证对应小节，不另增规则。

1. 「我的」只有用户登录。默认是密码登录。可以切换验证码登录，并可以重置密码。未录入，或管理员记录已删除的手机号，登录后看不到「进入后台」。手机号还在管理员记录里时，登录后看到「进入后台」。点击后进入项目列表。管理端请求核对当前登录手机号还在管理员记录里。这次核对不发送验证码。未登录、未录入或记录已删除时拒绝。不能在页面上新增或删除管理员。用户登录通过后留在「我的」。
2. 未登录可以打开项目、项目详情中的「善款」和善款捐赠明细。并符合第 6.1 节的可见与不可见字段。
3. 先创建捐款身份。这时可以还没有善款。再单笔录入，查询并添加该身份。打开页面时不列出全部身份。只生成一笔善款。身份资料不变。手动绑定后可见。另一个手机号也可以绑定同一身份。
4. 在身份详情更正匿名、展示名和个人说明。不新增善款。即使用户已修改，管理人员仍可更正。保存后标记为「未修改」，修改时间清空。
   - 单笔录入不修改身份。
   - 标记为未修改时，导入会覆盖展示名。不改匿名、个人说明和备注。
   - 导入在有手机号时更新手机号，即使用户已修改。留空不改变。
   - 同一身份多行都生成善款。用户未修改时，展示名以最后一行为准。手机号以最后一条非空值为准。
   - 错误行阻止整批写入。
5. 导入同一个手机号到两个平台身份后，该手机号登录即同时看到两条身份。留空的身份不会因此自动认领。手机号格式错误则该行失败。
6. 用户修改展示名后，单笔录入仍然只新增善款。标记仍为用户已修改时，导入不再覆盖是否匿名、对外展示名、个人说明。管理人员更正后，标记改回未修改。之后导入又可以覆盖展示名。手机号不由捐款人修改，但仍随批量导入更新。该行有手机号就写入。留空不改变。
7. 一笔善款绑定到项目 A 后，不能再绑到 B。解除后可以绑到 B。A 的善款合计减少。已完成和已关闭的项目也能接收绑定和开销。超额开销保存成功，并显示超支。
8. 善款不能改金额和日期。金额或日期有误时，作废后再重新导入。作废后从善款列表移出，记入「作废善款」，不再挂项目。挂过项目的，项目合计减去这笔。必须填写原因，原因写入作废记录的备注。批量作废按订单编号逐行预览。任一行失败则整批不写入。成功后可在「作废善款」按订单编号、身份和捐款日期，以及作废日期起止查找。
9. 创建项目先点「添加受益人」展开。尚未加入本项目的档案按更新时间倒序分页。桌面默认每页 10 条。移动每页固定 5 条。追加受益人同样分页。未添加受益人不能保存。从受益人详情创建时，该受益人已经添加且不能移除。只剩一名受益人时不能再移除。
10. 受益人绑定后，所在项目显示「包含我」。看不到其他受益人。包含自己的项目直接列在「我的受益」下。不另开页面，也不另写「受益项目」。一个手机号不能同时绑定两名受益人。两个手机号可以绑定同一档案。没有对应身份的新手机号登录后，捐赠身份和受益人都给出可展开的绑定入口。还没绑定受益人时，只说明绑定后才会列出项目。
11. 只有进行中的项目能发布进展。已有进展可编辑、可删除。删除后，公开页面和管理端都不再展示。
