## 1. 概述

微光是面向公益机构的资金透明管理工具。管理人员录入善款时先形成捐款身份，再记下每一笔金额；创建项目时必须指定受益人，再把整笔善款绑定到一个项目并记录开销。

- 捐款人用手机号登录。身份上的手机号一致时自动认领，也可以再手动绑定其他平台身份。
- 受益人登录后绑定唯一 ID，从而认出哪些项目包含自己。
- 项目、项目详情中的「善款」和善款捐赠明细对所有人公开。敏感身份不进入公开页面，规则见第 6 节。

优先级：未标注的功能为 P0，标注 P1 的为本期应交付。

## 2. 角色与流程

同一个人可以既捐款又受助：用同一个手机号登录后认领捐款身份，并绑定一名受益人。

| 角色 | 怎么进入 | 主要事情 |
| --- | --- | --- |
| 管理人员 | 预先录入且启用的手机号。先完成用户登录，「我的」出现「进入后台」，点击后进入项目列表 | 记账、立项、绑定善款、登记开销、维护受益人 |
| 捐款人 | 任意手机号，密码或短信验证码 | 查看自己的善款去向，修改已认领身份的对外资料 |
| 受益人 | 同上，再绑定姓名和唯一 ID | 查看包含自己的项目和公开的捐款来源 |
| 未登录访客 | 不登录 | 查看公开的项目和善款明细 |

```text
预先录入管理员手机号 → 用户登录 → 「进入后台」→ 项目列表
        ↓
建立受益人 → 创建项目（必须带至少一名受益人）
        ↓
录入善款：生成或更新捐款身份，再新增善款
        ↓
整笔绑定到一个项目，并登记开销
        ↓
所有人查看公开页面
捐款人登录后认领身份；受益人登录后绑定唯一 ID
```

```text
平台 + 平台用户 ID → 一条捐款身份 → 多笔善款 → 最多一个当前项目 → 项目开销
登录手机号 → 自动或手动认领捐款身份
受益人 → 至少一个 → 项目
登录手机号 → 绑定一名受益人
```

金额在服务端用人民币计算，大于 0，最多两位小数。

```text
一笔未作废善款最多一条有效绑定，绑定金额等于善款全额
项目善款合计 = 有效绑定的未作废善款金额之和
项目开销合计 = 未作废开销之和
项目结余 = 善款合计 - 开销合计
超支 = 结余 < 0
```

同一捐款身份、同一受益人档案，允许多个手机号同时认领。解除绑定只影响当前手机号。认领和绑定不提供物理删除。已解除、已作废的数据不出现在公开页面。

## 3. 登录与认领

全系统不设用户名和注册。登录默认使用手机号和密码，也可以切换为短信验证码。重置密码使用手机验证码。验证码 5 分钟内有效，同一手机号 1 小时内最多发送 5 次。密码至少 8 位。登录态过期后重新登录。退出登录清除本机登录态。短信验证码不写入业务日志。

管理端和用户端分开。管理人员不从用户端操作台账。捐款人和受益人不能进入管理端。

全系统只有一套登录，在用户端「我的」。打开时停在「密码登录」标签：手机号、密码和「登录」。页面不显示「登录」标题，登录内容上下居中。输入手机号后，若该号码留有密码提示，提示文字紧挨在「密码」右侧、密码输入框上方，不靠行尾。可切到「验证码登录」标签：手机号、验证码和「登录」。「重置密码」在页面底部。没有单独的管理员登录，也不在未登录时提供管理员入口。

### 3.1 管理员

记录含姓名、手机号、状态（启用或停用）。手机号在管理员中唯一。初始化时至少一名启用管理员。新增和停用由技术人员直接改数据库，管理端名单只读。停用后不能进入管理端，仍可使用用户登录，且须保留至少一名启用管理员。

启用管理员完成用户登录后，「我的」页头出现「进入后台」。未录入或已停用的手机号不出现该按钮。点击后直接离开用户端，进入项目列表。

管理端接口一律校验当前登录用户的手机号：登录态有效，且该手机号是启用中的管理员。未登录、未录入或已停用时拒绝请求，不返回台账。停用后该手机号仍可使用用户登录，但不能调用管理端接口。点击时若已停用，留在「我的」，页头不再显示「进入后台」，并提示「该手机号没有管理权限」。

### 3.2 用户登录与自动认领

用户端手机号不需要预先录入。验证码登录首次通过即建立个人空间，并留在「我的」。密码登录要求该手机号已经设置过密码；尚未设置或密码不正确时停在登录页，可改用验证码登录或重置密码。登录手机号是启用管理员时，页头另出现「进入后台」。

两种方式登录成功后，都找出捐款身份手机号与本次登录手机号相同、且当前手机号尚未认领的身份，自动建立认领。这些身份出现在捐赠身份列表中；打开一条后，捐款列表展示该身份下的未作废善款。同一次登录可以认领多条身份，已认领的不重复建立。

重置密码在登录页进入。填写手机号、短信验证码、新密码和确认新密码，并可填写密码提示，提示非必填。验证码通过且两次密码一致后写入新密码和密码提示，回到登录页，用新密码登录。留空则该手机号不再保留密码提示。验证码错误、过期，或两次密码不一致时停在重置页。

没有匹配手机号的身份，按第 3.3 节手动绑定。受益人的「包含我」要等第 3.4 节绑定成功后才出现。一个登录手机号可以同时认领多条捐款身份，并绑定一条受益人档案。

### 3.3 手动绑定捐款身份

捐款人填写「平台 + 平台用户 ID」。平台使用第 4 节的同一份清单。平台用户 ID 去掉首尾空格后精确匹配，区分大小写。

该身份下至少有一笔未作废善款、且当前手机号尚未认领时，提交绑定即认领，不展示笔数和金额合计，也不再进入确认页。没有匹配身份，或没有未作废善款时，提示「未找到对应捐款记录」，不保留认领。

一个手机号可以绑定多个身份。重复绑定提示已绑定。多个手机号可以绑定同一个身份，看到的是同一条身份及其善款。解除后，该手机号的捐赠身份列表和捐款列表不再显示这些善款；身份、其他认领、善款和项目绑定不受影响。

### 3.4 绑定受益人

提交姓名和唯一 ID，与档案去掉首尾空格后一致即绑定成功。绑定在「我的」的「我的受益」里展开和收起，不另开页面。提交后表单收起，包含自己的项目列在这个标题下，受益人姓名和脱敏号码在项目列表上方，不再显示「绑定受益人身份」。不一致或档案不存在时，统一提示「未找到匹配的受益人信息」，不说明是哪一项不对。

一个手机号同时只能绑定一个受益人档案，更换前先解除。多个手机号可以绑定同一个档案。解除后，该手机号不再显示「包含我」；档案、项目和其他手机号上的绑定仍保留。

### 3.5 捐款人修改已认领的身份

可以修改是否匿名、对外展示名、个人说明。不能修改平台、平台用户 ID 和手机号。

保存上述任意一项后，身份标记为「用户已修改」并记录修改时间。多个登录手机号认领同一身份时，任一手机号保存都会加上标记。捐款人之后仍可继续修改这三项。管理人员随时可以更正这三项，即使用户已经修改过。管理人员保存后，标记改回「未修改」，修改时间清空。单笔录入不修改身份资料。标记为「未修改」时，导入仍可覆盖对外展示名；标记为「用户已修改」时，导入不再覆盖是否匿名、对外展示名、个人说明。管理人员把标记改回未修改后，下一次导入重新按未修改处理。手机号只随批量导入更新，不受「用户已修改」限制，覆盖范围见第 4.2 节。

## 4. 捐款身份与善款

身份回答「这个人对外是谁」，善款回答「这一笔钱是多少」。身份键为「平台 + 平台用户 ID」，同一个键只有一条身份。同一身份下的多笔善款都显示该身份当前的对外资料，不在每笔善款上另存一份。

平台清单首期为微信支付、支付宝。后续版本追加时，录入、导入和手动绑定使用同一份清单。

### 4.1 字段

捐款身份和善款分开。平台、平台用户 ID、是否匿名、对外展示名、个人说明、手机号属于捐款身份。金额、捐款日期、订单编号、备注属于善款。

捐款身份在「捐款身份」列表中创建。创建时填写身份字段，不产生善款。

| 字段 | 创建身份 | 批量导入 | 说明 |
| --- | --- | --- | --- |
| 平台 | 必填 | 必填 | 平台清单中的一项。创建后不能修改 |
| 平台用户 ID | 必填 | 必填 | 最长 64 个字符。与平台组成身份键。创建后不能修改 |
| 是否匿名 | 必填，默认「是」 | 不录入 | 导入新建时写「是」。导入永不修改此项。单笔录入不修改 |
| 对外展示名 | 选填 | 选填 | 未匿名时公开。为空时公开页面显示「{平台}捐款人」 |
| 个人说明 | 选填，不超过 200 字 | 不录入 | 用户端善款页和项目详情的善款不展示。导入新建时为空，导入永不修改。单笔录入不修改 |
| 手机号 | 选填 | 选填 | 11 位中国大陆手机号。捐款人不能修改。创建时可以填写。批量导入有值时更新，留空不改变；用户已修改也不阻止这次更新 |

| 字段 | 单笔录入 | 批量导入 | 说明 |
| --- | --- | --- | --- |
| 捐款身份 | 必填，查询后添加一条已有身份 | 按本行的平台和平台用户 ID 匹配；没有则创建 | 单笔录入不新建身份，也不修改身份资料。查询前不列出全部身份 |
| 金额 | 必填 | 必填 | 大于 0，最多两位小数 |
| 捐款日期 | 必填 | 必填 | 不得晚于录入当天 |
| 订单编号 | 必填 | 必填 | 最长 64 个字符，全库唯一。创建后不能修改。批量作废按它查找。不进入公开页面 |
| 备注 | 选填 | 不录入 | 仅管理人员可见。导入生成的备注为空。不作单独修改；作废原因追加进备注 |

### 4.2 创建身份、单笔录入与导入覆盖

管理端展示捐款身份列表，并可创建捐款身份。创建只写入身份字段，「用户已修改」为「否」，不产生善款。同一身份键已存在时不能再次创建。平台和平台用户 ID 创建后不能改。

单笔录入按平台用户 ID、手机号或对外展示名查询已有捐款身份，从结果中添加一条，再填写金额、捐款日期、订单编号和备注。桌面端订单编号独占一行，金额和捐款日期并排，备注独占一行。移动端在查询捐款身份和录入捐款信息之间有分割线，四项各占一行，顺序为订单编号、金额、捐款日期、备注。查询前和空条件都不列出全部身份。桌面端这三项查询条件都直接展示，不折叠。查询结果和已选身份展示完整手机号，不脱敏，每条一行。本页不出现平台、平台用户 ID、是否匿名、对外展示名、个人说明和手机号的填写项。没有匹配的身份时不能保存，先去创建。保存后只新增一条未绑定善款，挂在所选身份下，身份资料保持不变。

管理人员在身份详情随时可以更正匿名、对外展示名和个人说明，即使用户已经修改过。不必为此新增善款。保存后标记为「未修改」，修改时间清空。原先已是未修改的，保持未修改。

批量导入使用 Excel（`.xlsx`）。列：平台、平台用户 ID、对外展示名、手机号、金额、捐款日期、订单编号。不包含是否匿名、个人说明、备注。只读第一个工作表，第一行是表头。平台用户 ID、手机号、订单编号按文本读取。页面提供模板下载。模板见第 13 节。整批成功后，原文件存入导入目录；任一行失败则整批不写入，也不保存文件。

导入前预览并标错。身份未修改时，标明展示名将更新，手机号将写入或因留空不改变。身份已修改时，标明展示名本次不覆盖；手机号有值仍标明将写入，留空仍标明不改变。全部行通过后按从上到下一次写入；任一行失败则整批不写入，并返回行号和原因。单次最多 500 行。

每一行：

1. 身份不存在则创建：匿名为「是」，个人说明为空，「用户已修改」为「否」。展示名用本行内容。手机号有值则写入。
2. 身份已存在且用户未修改：用本行展示名覆盖，空值也覆盖。不改匿名和个人说明。手机号有值则更新，留空不改变原手机号。
3. 身份已存在且用户已修改：不改匿名、展示名、个人说明。手机号有值则更新，留空不改变原手机号。
4. 新增一条未绑定善款，挂在本行身份下，写入本行订单编号，备注为空。

同一身份在一批中出现多行时，每行各生成一笔善款。用户未修改时，展示名以最后一行为准。手机号不论用户是否已修改，都以本批最后一条非空手机号为准；全部留空则不改变。

导入写入或更新手机号后：该号码已有登录身份则立即认领，否则下次登录再认领。旧认领保留。捐款人不能自行改手机号。

校验：平台在清单内；平台用户 ID 非空且不超过 64 个字符；手机号为空或为 11 位中国大陆手机号；金额大于 0 且最多两位小数；日期为 `YYYY-MM-DD` 且不晚于当天；订单编号非空、不超过 64 个字符，且在本批和已有善款中都不重复。

示例：先创建一条捐款身份，匿名为「是」，此时还没有善款。单笔录入查询并添加它，只新增一笔未绑定善款，身份仍是匿名。用户尚未修改时，在身份详情改为不匿名，展示名「张三」，个人说明「希望用于助学」，不新增善款，标记仍是未修改。用户随后把展示名改成「张先生」，标记变为用户已修改。之后单笔录入仍然只新增善款。导入不再覆盖展示名。捐款人不能改手机号。导入行若带了手机号，身份手机号仍更新为该值；留空则保持原手机号。管理人员再次更正展示名后，标记改回未修改，修改时间清空。之后导入又可覆盖展示名。

### 4.3 管理端列表、状态、更正与作废

捐款身份列表展示平台、平台用户 ID、当前展示名、是否匿名、手机号、是否用户已修改、名下未作废善款笔数。按平台、平台用户 ID、手机号查询并分页。从这里创建身份，或打开身份详情。手机号脱敏，点击后查看完整号码。平台用户 ID 完整展示。尚无善款的身份也留在列表中。

善款列表默认按捐款日期倒序并分页。桌面和移动都直接查询订单编号、捐款身份平台 ID、捐款身份姓名或手机号、绑定状态；捐款日期起和捐款日期止收在「更多条件」。桌面点「查询」后生效。移动端改完即查。桌面表格展示善款编号、金额、捐款身份姓名、日期、状态、项目。捐款平台、订单编号、备注默认折叠。移动卡片第一行是金额和捐款身份姓名，日期在右；第二行是善款编号；第三行是状态和项目。移动端展开后不标注字段名：第一行是捐款平台和订单编号，第二行是备注。操作是打开身份、作废。已作废的记录不显示作废。捐款身份姓名读所属身份的当前公开称呼。订单编号在管理端完整展示。没有项目时为「—」，没有备注时为「无」。

管理端没有善款详情页。身份详情展示身份字段、手机号、修改标记、修改时间，以及名下善款。公开列表的字段见第 6 节。

| 状态 | 条件 |
| --- | --- |
| 未绑定 | 未作废，且没有有效项目绑定 |
| 已绑定 | 未作废，且有一条有效项目绑定 |
| 已作废 | 管理人员作废。不再进入可绑定列表和捐款列表 |

状态由系统计算。善款不能更正金额和日期。金额或日期有误时，作废这笔后再重新导入。已作废不能改。善款不能改挂到另一个身份。身份键录错时，不能改原身份的平台和平台用户 ID，需另建正确身份，再作废这笔后选取正确身份重新单笔录入。

作废页展示这笔的善款编号、订单编号、金额、捐款日期、绑定状态、当前项目、备注，以及所属身份的平台、平台用户 ID、是否匿名、对外展示名、个人说明、完整手机号和是否用户已修改。作废对未绑定和已绑定善款都可以直接做，且必须填写原因。已绑定的先解除项目绑定，绑定变为「已解除」并不再计入项目合计，然后状态改为「已作废」。未绑定的直接改为「已作废」。两步在同一次操作里完成。原因追加到备注末尾，原备注保留。不设作废原因字段。已作废不能再次作废。身份下善款全部作废后，身份仍保留。

批量作废与批量导入同一路径：下载 Excel 模板、上传 `.xlsx`、预览、全部通过后确认写入。列是订单编号、作废原因。订单编号按文本读取。按订单编号找到已有善款。预览标明将作废；已绑定的标明先解除再作废，以及原因将追加到该笔备注。订单编号为空、订单编号不存在、本批订单编号重复、原因为空或已作废，都算该行失败。任一行失败则整批不写入，不保存文件，并返回行号和原因。全部通过后，原文件存入作废目录。导入目录和作废目录分开，都在「导入文档」页提供下载。单次最多 500 行，超过时不逐行写入。模板见第 13 节。

编号：善款 `SK` + 年月日 + 4 位当日流水。

## 5. 项目、受益人、绑定与开销

### 5.1 受益人档案

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 姓名 | 是 | 管理人员可见。绑定成功的受益人本人可见自己的姓名 |
| 唯一 ID | 是 | 推荐身份证号。档案内唯一。加密存储 |
| 备注 | 否 | 仅管理人员可见 |
| 更新日期 | 系统写入 | 最近一次保存档案的日期。新建项目的「添加受益人」和追加受益人都按它倒序分页，只含尚未加入本项目的档案。桌面默认每页 10 条，移动每页固定 5 条 |

列表和详情中的唯一 ID 保留前 3 位和后 4 位，点击后查看完整号码。受益人列表按姓名、唯一 ID 查询并分页。一名受益人可以加入多个项目。

### 5.2 创建项目与状态

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 项目名称 | 是 | 不超过 50 字 |
| 项目简介 | 是 | 公开 |
| 开始日期 | 是 | |
| 受益人 | 是 | 至少一名。先点「添加受益人」再展开，展开后文字为「收起添加受益人」。展开后按更新时间倒序分页，也可按姓名或唯一 ID 查询，可添加多名。桌面端查询结果用表格，默认每页 10 条。移动端查询结果用卡片，每页固定 5 条，显示页码，并有上一页、下一页。已添加的不分页。移动端已添加的卡片和查询结果卡片上，脱敏唯一 ID 都紧跟姓名，下方展示备注。没有备注时显示「无」。移动端查询结果不画分隔线 |

未添加受益人不能保存，提示「请至少选择一名受益人」。入口有两处：项目列表的「新建项目」；受益人详情的「创建项目」。从受益人详情进入时，当前受益人已经添加且不能移除，其他人在展开「添加受益人」后，按更新日期倒序分页。追加受益人只在进行中的项目上可用，只在尚未关联到本项目的档案中按更新日期倒序分页。两处都按更新时间倒序分页，桌面默认每页 10 条，移动每页固定 5 条，也可按姓名或唯一 ID 查询。已完成或已关闭不能追加，要先改回进行中。已在项目中的人不提供添加。

创建后为「进行中」，善款合计、开销合计、结余均为 0。项目没有封面。只有进行中可以修改名称、简介、开始日期；已完成、已关闭要先改回进行中。

项目列表可以删除项目，不限状态。点「删除」后弹出确认，写明项目名称。确认后该项目从管理端和公开项目列表消失。取消则不删除。

| 状态 | 含义 | 可以做 | 不能做 |
| --- | --- | --- | --- |
| 进行中 | 正在执行 | 桌面和移动相同。页头：编辑、标记完成、标记关闭。受益人标题同行居右：追加受益人。进展标题同行居右：发布进展。善款标题同行居右：绑定善款。开销标题同行居右：登记开销 | |
| 已完成 | 活动结束 | 绑定善款、登记开销、改回进行中、编辑已有进展、删除已有进展 | 编辑项目、追加受益人、移除受益人、新增进展 |
| 已关闭 | 暂停 | 与已完成相同 | 与已完成相同 |

解除善款绑定、作废开销在任何状态都可以做。移除受益人只在进行中。已完成或已关闭要先改回进行中。移除后至少保留一名受益人，只剩一名时提示「项目至少保留一名受益人」。重复关联不新增。受益人尚未登录时，关联仍然有效，绑定成功后即可看到「包含我」。管理端桌面和移动项目详情都一次列出该项目全部受益人，展示备注，不查询、不分页；桌面端进展、善款和开销全部展示，不折叠。移动端进展默认只展示前 2 条，每次再展示 2 条。移动端善款和开销默认只展示前 5 条，每次再展示 5 条。这三段都能收起。桌面端进展用纵向卡片横向排列。卡片内标题在左、日期在右，同一行，并展示正文和图片。多张图片一次只显示一张，点「下一张」切换。操作只有编辑和删除。移动端进展默认只展示前 2 条，多于 2 条时点「查看更多进展」每次再展示 2 条。已经多看过、且仍有未展示记录时，「收起更多进展」与「查看更多进展」并排。全部展示后只留下「收起更多进展」。卡片同样展示正文和图片，多张图片一次只显示一张，点「下一张」切换，操作也是编辑和删除。删除后管理端和公开页面都不再展示该条。

编号：项目 `XM` + 年月日 + 4 位当日流水。

### 5.3 善款绑定

管理人员从项目详情把一笔「未绑定」善款绑到任意状态的项目。不填写金额，绑定的是全额。未作废且未绑定的善款按捐款日期倒序分页后确认。桌面默认每页 10 条，移动每页固定 5 条。也可按订单编号、善款编号或平台用户 ID 查询。空条件仍是这份分页名单。

保存后生成有效绑定，善款变为「已绑定」，项目善款合计和结余重算。已绑定的善款不能再绑到其他项目；要更换就先解除再绑。并发时只有一个请求成功，后到的提示该善款已绑定项目。

解除不填原因。绑定变为「已解除」并不再计入合计，善款回到「未绑定」。公开页面只显示有效绑定。未绑定善款在捐款列表和善款捐赠明细中显示「尚未安排到具体项目」。

### 5.4 开销

进行中、已完成、已关闭都可以登记。开销不改写善款，也不分摊到某一笔善款。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 开销日期 | 是 | 不得晚于录入当天 |
| 类别 | 是 | 物资采购、交通食宿、人员补贴、其他 |
| 金额 | 是 | 大于 0，最多两位小数 |
| 说明 | 是 | 公开 |

保存后重算开销合计和结余。开销可以大于善款，此时标记「超支」并仍然保存。未作废记录可改日期、类别、金额、说明。作废后不计入合计，公开页面不可见，不强制填原因。

开销在项目详情中按日期倒序。管理端可见作废记录。编号：`KX` + 年月日 + 4 位当日流水。

### 5.5 项目进展（P1）

仅进行中的项目可以发布。一条进展包含日期、标题、正文、图片。按时间倒序出现在公开项目详情。已有进展可以编辑，也可以删除。删除后管理端和公开页面都不再展示。已完成和已关闭不能新增，已发布的仍可编辑或删除。

编号：`JZ` + 年月日 + 4 位当日流水。

## 6. 谁能看到什么

传输使用 HTTPS。手机号、平台用户 ID、受益人唯一 ID 为敏感信息。页面上手机号和唯一 ID 默认保留前 3 位和后 4 位。管理端台账展示完整平台用户 ID；身份手机号和受益人唯一 ID 点击后再看完整值。

### 6.1 无需登录

未登录可打开项目列表、项目详情和善款捐赠明细。各页字段、查询、空状态和卡片见《原型图描述文档》。

项目列表不显示结余、项目编号和「超支」，默认按开始日期倒序，按项目名称、状态查询。项目详情按进展、善款、开销排列。进展按时间倒序，用卡片展示正文和图片，多张图片一次只显示一张。默认只展示前 2 条，点「查看更多进展」每次再展示 2 条。已经多看过、且仍有未展示记录时，「收起更多进展」与「查看更多进展」并排。全部展示后只留下「收起更多进展」。善款只含有效绑定，开销只含未作废。这两段默认展示 5 条，点「查看更多」每次再展示 5 条，并能收起。善款捐赠明细含全部未作废善款，按捐款日期倒序，按绑定状态、捐款日期查询，不按平台查询。未绑定不能点进项目。

公开称呼：匿名为「匿名捐款人」，不显示对外展示名。未匿名为对外展示名；展示名为空时用「{平台}捐款人」。用户端善款页和项目详情的善款都不展示个人说明。个人说明最长 200 字。

公开页面不展示：平台用户 ID、订单编号、身份手机号、善款备注、受益人姓名、唯一 ID、受益人备注、他人的「包含我」和「我的捐款」、已作废善款、已解除绑定、已作废开销。已删除的进展不在公开页面。

### 6.2 登录后多看到的标记

认领了对应捐款身份的用户，在项目详情的「善款」里自己的行上看到「我的捐款」。

「我的」的卡片、按钮和空状态见《原型图描述文档》。身份已经列在页面上，不再单独统计已认领身份数，也不按平台筛选。金额汇总为累计捐款金额、已进入项目的金额、尚未安排的金额。没有任何认领时给出手动绑定入口。绑定捐赠身份在「我的」本页展开，提交绑定后仍留在「我的」。打开一条身份进入该身份的捐款列表。页首是这条捐赠身份，每笔只显示金额、绑定状态、时间和绑定项目。已绑定的可进入项目公开页。不展示管理备注和平台用户 ID。解除绑定先弹出确认，确认后才解除并回到「我的」；取消则不解除。

绑定受益人后，包含自己的项目直接列在「我的受益」下，不另写「受益项目」，按开始日期倒序，不另开页面，也不按名称或状态筛选。简介在项目详情中查看。没有时说明「暂时没有包含我的项目」。受益人姓名和脱敏号码在项目列表上方。打开一条后，项目详情显示「包含我」，返回仍回到「我的」。未绑定时，「绑定受益人身份」在项目列表上方展开和收起，其下只说明绑定后才会列出，不展示项目。绑定成功后不再显示这个入口。这些空状态不代替公开列表。

个人页顶部把脱敏登录手机号和退出并排靠右，不换行。登录手机号是启用管理员时，「进入后台」在最右。

### 6.3 仅管理人员

全部台账、善款备注、身份手机号、受益人名单和完整唯一 ID、作废开销、已解除绑定。用户侧项目列表只显示状态标签。项目详情上的超支标记，管理端项目列表和详情同样显示。管理端这些列表的表格、卡片和查询见《原型图描述文档》。

知道「平台 + 平台用户 ID」的人，用自己的手机号验证后就可以认领该身份，并修改其对外资料。不能修改该身份的手机号。知道姓名和唯一 ID 的人，可以绑定并看到哪些项目包含该受益人。

## 7. 页面

各页面上有什么，见《原型图描述文档》。

管理端和用户端的入口都是项目列表，功能顺序也一致，先项目，后善款。各接口校验当前登录手机号。未绑定善款、进行中的项目和超支项目在对应列表里作为查询条件，不另设首页。把已有对象加进另一条记录时先查询再添加，查询前不列出全部对象。新建项目的「添加受益人」和追加受益人都按更新时间倒序分页，只含尚未加入本项目的档案。选择未绑定善款按捐款日期倒序分页。这几处桌面默认每页 10 条，移动每页固定 5 条。对象自己的列表页仍展示台账。

公开页面：全部项目、项目详情（含进展、善款、开销）、善款捐赠明细。底部为「项目」「善款」「我的」。

「我的」：未登录时只有用户登录。登录和自动认领后留在「我的」，展示捐赠身份列表、某一身份的捐款列表、包含我的项目列表、个人与退出。启用管理员另有「进入后台」。

## 11. 验收

P0 按下面的路径核对。每条只验证对应小节，不另增规则。

1. 「我的」只有用户登录，默认是密码登录，可切换验证码登录，并可重置密码。未录入或已停用的手机号登录后看不到「进入后台」。启用管理员登录后看到「进入后台」，点击后进入项目列表。管理端接口校验当前登录手机号为启用管理员，这次校验不发送验证码；未登录、未录入或已停用时拒绝。不能在页面上增删管理员。用户登录通过后留在「我的」。
2. 未登录可打开项目、项目详情中的「善款」和善款捐赠明细，并符合第 6.1 节的可见与不可见字段。
3. 先创建捐款身份，此时可以还没有善款。再单笔录入，查询并添加该身份，打开页面时不列出全部身份。只生成一笔善款，身份资料不变。手动绑定后可见；另一个手机号也可以绑定同一身份。
4. 在身份详情更正匿名、展示名和个人说明，不新增善款。即使用户已修改，管理人员仍可更正。保存后标记为「未修改」，修改时间清空。单笔录入不修改身份。标记为未修改时，导入会覆盖展示名，不改匿名、个人说明和备注。导入在有手机号时更新手机号，即使用户已修改；留空不改变。同一身份多行都生成善款。用户未修改时展示名以最后一行为准。手机号以最后一条非空值为准。错误行阻止整批写入。
5. 导入同一个手机号到两个平台身份后，该手机号登录即同时看到两条身份。留空的身份不会因此自动认领。手机号格式错误则该行失败。
6. 用户修改展示名后，单笔录入仍然只新增善款。在标记仍为用户已修改时，导入不再覆盖是否匿名、对外展示名、个人说明。管理人员更正后标记改回未修改，之后导入又可覆盖展示名。手机号不由捐款人修改，但仍随批量导入更新：该行有手机号就写入，留空不改变。
7. 一笔善款绑定到项目 A 后不能再绑到 B。解除后可以绑到 B，A 的善款合计减少。已完成和已关闭的项目也能接收绑定和开销。超额开销保存成功并显示超支。
8. 善款不能更正金额和日期。金额或日期有误时，作废后再重新导入。作废可以直接做：已绑定的先解除项目绑定，再改为已作废；未绑定的直接改为已作废。原因追加在备注中，没有单独的作废原因字段。已作废不能再次作废。批量作废按订单编号逐行预览，任一行失败则整批不写入。
9. 创建项目先点「添加受益人」展开，尚未加入本项目的档案按更新时间倒序分页。桌面默认每页 10 条，移动每页固定 5 条。追加受益人同样分页。未添加受益人不能保存。从受益人详情创建时，该受益人已经添加且不能移除。只剩一名受益人时不能再移除。
10. 受益人绑定后，所在项目显示「包含我」，看不到其他受益人。包含自己的项目直接列在「我的受益」下，不另开页面，也不另写「受益项目」。一个手机号不能同时绑定两名受益人；两个手机号可以绑定同一档案。没有对应身份的新手机号登录后，捐赠身份和受益人都给出可展开的绑定入口；尚未绑定受益人时，只说明绑定后才会列出项目。

P1 另验：只有进行中的项目能发布进展。已有进展可编辑、可删除，删除后公开页面和管理端都不再展示。
