# 微光用户用例手册

| 项 | 内容 |
| --- | --- |
| 产品名称 | 微光 |
| 手册版本 | V1.0 |
| 依据文档 | 《微光产品需求文档》V1.0（2026-10-16） |
| 页面展示 | 《原型图描述文档》 |
| 读者 | 管理人员、捐款人、受益人、测试、实施 |
| 本期范围 | 单机构。项目进展为 P1，本期一并交付 |

本手册按真实使用顺序写。每一步都说明：做完之后停在哪个页面、接下来可以点什么、点完又到哪里。页面上有什么以《原型图描述文档》为准。

管理端和用户端分开。管理人员在管理端记账、立项；捐款人和受益人在用户端查看和认领。同一个人可以既是捐款人又是受益人，用同一个手机号登录用户端即可。管理人员若也要认领自己的捐款或绑定受益人，使用用户端的「我的」标签，不在管理端做这两件事。

用户端首页有三个标签：「项目」「善款」「我的」。打开首页时停在「项目」。三个标签在列表、详情和登录过程中一直显示，当前标签高亮。

## 1. 三种使用方式

| 使用方式 | 怎么进入 | 打开后首先看到 | 本手册章节 |
| --- | --- | --- | --- |
| 管理员 | 先在「我的」完成用户登录。手机号已预先录入并处于启用时，页头出现「进入后台」，点击后进入项目列表 | 项目列表 | 第 3 章 |
| 未登录用户 | 直接打开用户端首页 | 「项目」标签 | 第 4 章 |
| 登录用户 | 在「我的」用任意手机号 + 密码，或短信验证码 | 「我的」标签 | 第 5 章 |

全系统没有用户名和注册，也没有单独的管理员登录。默认用手机号和密码登录，可切换短信验证码登录。重置密码使用手机验证码。验证码 5 分钟内有效，同一手机号 1 小时内最多发送 5 次。密码至少 8 位。登录态过期后重新登录。退出登录清除本机登录态。管理端接口另校验当前登录手机号是否为启用管理员，这次校验不发送验证码。

金额在服务端按人民币计算，必须大于 0，最多两位小数。

编号规则：

| 对象 | 编号 |
| --- | --- |
| 善款 | `SK` + 年月日 + 4 位当日流水 |
| 项目 | `XM` + 年月日 + 4 位当日流水 |
| 开销 | `KX` + 年月日 + 4 位当日流水 |
| 项目进展 | `JZ` + 年月日 + 4 位当日流水 |

手机号、受益人唯一 ID 在页面上默认保留前 3 位和后 4 位，例如 `138****0000`。管理端的身份手机号、受益人唯一 ID 可以点击后再看完整值。管理端台账直接展示完整平台用户 ID。用户端「我的」页头展示脱敏后的登录手机号。

公开称呼：

| 身份情况 | 公开页面上的称呼 |
| --- | --- |
| 匿名 | 匿名捐款人 |
| 未匿名，对外展示名有内容 | 对外展示名原文 |
| 未匿名，对外展示名为空 | `{平台}捐款人`，例如「微信支付捐款人」 |

用户端「善款」页和项目详情的善款都不展示个人说明。

已作废善款、已解除的善款绑定、已作废开销，不出现在公开页面。已删除的进展也不出现。

平台首期只有两项：微信支付、支付宝。录入、导入、手动绑定使用同一份清单。

## 3. 管理员

管理员使用管理端。手机号由技术人员预先写入数据库，状态为启用或停用。手机号在管理员中唯一。系统初始化时至少有一名启用管理员。新增和停用在数据库中完成，管理端名单只读。停用后仍可使用用户登录，但不能调用管理端接口，并且必须始终保留至少一名启用管理员。

捐款人和受益人不能进入管理端。管理员不在用户端做录入、导入、绑定项目、登记开销这些台账操作。

管理端同时有桌面和移动两种布局，支持最近两个版本的 Chrome、Edge。桌面使用侧栏。移动端从屏幕宽度 360px 起可以完成录入、导入、作废、绑定项目和登记开销，底部入口为「项目」「善款」「受益人」「其他」。「其他」默认折叠，展开后进入「捐款身份」「导入文档」或「管理员」。桌面侧栏并列显示六项：项目、善款、受益人、捐款身份、导入文档、管理员。

各页怎么查询、怎么分页、卡片和折叠怎么排，见《原型图描述文档》。下面各列表写的「清除」只出现在桌面端。

管理端登录后的固定入口：

| 入口 | 页面 |
| --- | --- |
| 项目 | 项目列表。从「我的」点「进入后台」后首先进入这里 |
| 善款 | 善款列表 |
| 受益人 | 受益人列表 |
| 捐款身份 | 捐款身份列表 |
| 导入文档 | 导入成功和作废成功的 Excel，分两个目录，可以下载 |
| 管理员 | 管理员名单 |

移动端把「捐款身份」「导入文档」和「管理员」收在底部「其他」里，默认折叠。桌面侧栏六项并列，顺序与上表相同。

### 3.1 进入管理端

**操作：** 先在「我的」用手机号和密码，或短信验证码，完成用户登录。登录手机号是启用中的管理员时，「我的」页头出现「进入后台」。点击「进入后台」。

未登录时没有「进入后台」。登录手机号未录入，或管理员已停用时，页头也没有「进入后台」。

**页面：项目列表**

离开用户端，进入项目列表，见 3.11。进行中的项目和超支项目在项目列表里筛选。未绑定善款在善款列表里按绑定状态筛选。

管理端每个接口都校验这次请求里的当前登录手机号：登录态仍然有效，且该手机号是启用中的管理员。这次校验不发送验证码。未登录、手机号未录入或已停用时，接口拒绝，不返回台账。若点击时已经停用，留在「我的」，页头不再显示「进入后台」，并提示「该手机号没有管理权限」。

没有用户名、注册和管理员自助添加。密码在用户端登录页设置和重置。

### 3.2 查看并创建捐款身份

**页面：捐款身份列表**

身份键是「平台 + 平台用户 ID」。列表展示当前身份资料，不从某一笔善款上另取一份。尚无善款的身份也在列表中。

每一行：

- 平台
- 平台用户 ID（完整）
- 当前展示名
- 当前是否匿名
- 手机号（脱敏，点击后看完整号码）
- 用户已修改
- 名下未作废善款笔数

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 按平台、平台用户 ID、手机号查询 | 仍是捐款身份列表第 1 页 |
| 桌面端改每页条数、点上一页或下一页、点附近页码、首页或末页，或前往指定页；移动端滑到列表底部 | 仍是捐款身份列表。条件不变。当前页有标记；移动端接上下一页，直到全部加载完。总数在底部 |
| 打开一行 | 身份详情，见 3.9 |
| 创建捐款身份 | 创建捐款身份 |
| 清除 | 全部捐款身份的第 1 页 |

**页面：创建捐款身份**

只创建身份，不产生善款，也不把身份标成「用户已修改」。

| 字段 | 页面要求 |
| --- | --- |
| 平台 | 必填。微信支付或支付宝。创建后不能改 |
| 平台用户 ID | 必填，最长 64 个字符。与平台组成身份键。创建后不能改 |
| 是否匿名 | 必填，默认「是」 |
| 对外展示名 | 选填 |
| 个人说明 | 选填，不超过 200 字 |
| 手机号 | 选填。11 位中国大陆手机号。捐款人不能修改 |

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 保存 | 校验通过后进入新身份的详情。名下还没有善款 |
| 取消 | 捐款身份列表，不产生身份 |

校验不通过时停在本页，并说明原因，例如：平台不在清单中、平台用户 ID 为空或超过 64 个字符、该身份键已经存在、个人说明超过 200 字、手机号不是 11 位。

### 3.3 查看善款列表

**页面：善款列表**

默认按捐款日期倒序。捐款身份姓名跟着身份现在的资料变，不保留录入那一刻的旧副本。没有项目时为「—」，没有备注时为「无」。

桌面用表格，列为善款编号、金额、捐款身份姓名、日期、状态、项目。默认每条一行，单元格和操作都不换行。捐款平台、订单编号（完整）、备注默认折叠，点「展开」后显示在该行下方，再点「收起」收回。操作从左到右是打开身份、作废，作废在最右。已作废的记录不显示作废。状态为未绑定、已绑定、已作废。

筛选直接展示订单编号、捐款身份平台 ID、捐款身份姓名/手机号、绑定状态下拉框。捐款日期起、捐款日期止收在「更多条件」。桌面点「查询」后生效。移动端改完即查，不显示「清除」和「查询」。姓名/手机号同时匹配公开称呼和手机号。

移动卡片第一行是金额和捐款身份姓名，日期在右；第二行是善款编号；第三行是状态和项目。捐款平台、订单编号、备注默认折叠，点「展开」后显示，再点「收起」收回。展开后不标注字段名：第一行是捐款平台和订单编号，第二行是备注。没有备注时显示「无」。操作从左到右是打开身份、作废，作废在最右。已作废的记录不显示作废。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 按订单编号、捐款身份平台 ID、捐款身份姓名或手机号、绑定状态、捐款日期查询。桌面点「查询」后生效；移动端改完即查 | 仍是善款列表第 1 页，继续按捐款日期倒序 |
| 桌面端改每页条数、点上一页或下一页、点附近页码、首页或末页，或前往指定页；移动端滑到列表底部 | 仍是善款列表。条件不变。当前页有标记；移动端接上下一页，直到全部加载完。总数在底部 |
| 清除（仅桌面） | 全部善款的第 1 页 |
| 展开 / 收起 | 仍是善款列表。展开后看到该行的捐款平台、订单编号、备注 |
| 打开身份 | 该笔所属捐款身份的详情 |
| 作废 | 作废善款。已作废的记录上没有这个操作 |
| 新建善款 | 单笔录入 |
| 批量导入 | 导入预览的文件选择 |
| 批量作废 | 选择作废文件，见 3.8 |

### 3.4 单笔录入善款

**操作：** 在善款列表点击「新建善款」。

**页面：单笔录入**

按平台用户 ID、手机号或对外展示名查询一条已有捐款身份，再添加。查询前和空条件都不列出全部身份。本页不填写、也不修改平台、平台用户 ID、是否匿名、对外展示名、个人说明和手机号。还没有身份时，先到捐款身份列表创建。

| 字段 | 页面要求 |
| --- | --- |
| 捐款身份 | 必填。桌面端平台用户 ID、对外展示名、手机号都直接展示，不折叠。查询命中后显示平台、平台用户 ID、当前公开称呼和完整手机号，不脱敏，每条一行。点「添加」后，已选身份同样展示完整手机号并排成一行，不能在本页改 |
| 订单编号 | 必填，最长 64 个字符，全库唯一。创建后不能改。批量作废按它查找。桌面端和移动端都排在最前，独占一行 |
| 金额 | 必填，大于 0，最多两位小数。桌面端与捐款日期并排。移动端独占一行 |
| 捐款日期 | 必填，格式 `YYYY-MM-DD`，不得晚于录入当天。桌面端与金额并排。移动端独占一行，排在金额之后 |
| 备注 | 选填。只有管理人员可见。桌面端和移动端都独占一行 |

移动端在查询捐款身份和录入捐款信息之间有一条分割线。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 查询 | 仍是单笔录入。有命中时只显示命中的身份 |
| 查询条件为空 | 仍是单笔录入，提示先输入条件，不列出身份 |
| 没有命中 | 仍是单笔录入，说明没有匹配的捐款身份 |
| 添加一条身份 | 仍是单笔录入。该身份成为本次身份，可移除后重新查询 |
| 保存 | 已添加身份且其余校验通过后，回到善款列表。新增一笔未绑定善款，善款编号形如 `SK202610130001`，并带上本次订单编号。身份资料不变 |
| 取消 | 善款列表，不产生善款 |
| 去创建捐款身份 | 创建捐款身份。本页尚未保存 |

校验不通过时停在单笔录入，并说明原因，例如：尚未添加捐款身份、订单编号为空、超过 64 个字符或与已有善款重复、金额不大于 0 或超过两位小数、日期格式不对或晚于今天。

保存成功后只新增一笔未绑定善款，挂在所选身份下，写入本次订单编号。不新建身份，也不覆盖匿名、展示名、个人说明和手机号。

### 3.5 预览并导入善款

**操作：** 在善款列表点击「批量导入」。

**页面：选择导入文件**

文件是 Excel（`.xlsx`）。只读第一个工作表，第一行是表头。平台用户 ID、手机号、订单编号按文本填写。模板列为：平台、平台用户 ID、对外展示名、手机号、金额、捐款日期、订单编号。文件中不包含是否匿名、个人说明、备注。单次最多 500 行。页面提供「下载模板」。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 下载模板 | 仍是选择导入文件，开始下载「善款导入模板.xlsx」 |
| 上传文件并预览 | 导入预览 |
| 取消 | 善款列表 |

**页面：导入预览**

每一行都标出将要发生的事，或标出错误。超过 500 行时不进入逐行写入，页面说明超出单次上限。

校验规则：

- 平台必须在清单内
- 平台用户 ID 非空且不超过 64 个字符
- 手机号为空，或为 11 位中国大陆手机号
- 金额大于 0 且最多两位小数
- 日期为 `YYYY-MM-DD`，且不晚于当天
- 订单编号非空、不超过 64 个字符，且在本批和已有善款中都不重复

身份处理在预览中这样标明：

| 这一行对应的身份 | 预览文字 |
| --- | --- |
| 还不存在 | 将新建身份：匿名为「是」，个人说明为空，「用户已修改」为否。展示名用本行内容。手机号有值则写入。并新增一笔未绑定善款，写入本行订单编号，备注为空 |
| 已存在，用户未修改 | 「展示名将更新」。手机号有值时标明「手机号将写入」；手机号留空时标明「手机号因留空不改变」。匿名和个人说明不改 |
| 已存在，用户已修改 | 「展示名本次不覆盖」。匿名、个人说明也不改。手机号有值时标明「手机号将写入」；手机号留空时标明「手机号因留空不改变」 |

### 3.6 善款没有单独详情页

管理端没有善款详情页。善款列表可以打开身份、作废。项目详情可以绑定善款、解除绑定、作废。身份详情列出名下善款，不能从这里打开某一笔。

善款不能更正金额和日期。金额或日期有误时，作废后再重新导入。善款不能改挂到另一个身份。身份键录错时，不能改原身份的平台和平台用户 ID，需另建正确身份。作废这笔后，选取正确身份重新单笔录入。已绑定的作废会先解除项目绑定。

### 3.7 金额和日期

善款不能更正金额和日期。金额或日期有误时，在善款列表或项目详情作废这笔，再按正确金额和日期重新导入。

**解除绑定**

## 4. 未登录用户

用户端首页有三个标签。未登录时：

| 标签 | 页内内容 |
| --- | --- |
| 项目 | 公开项目列表。打开一条进入项目详情 |
| 善款 | 公开的善款捐赠明细 |

未登录用户在「项目」和「善款」里查看公开内容。看不到平台用户 ID、订单编号、身份手机号、善款备注、受益人姓名、唯一 ID、受益人备注，也看不到「我的捐款」和「包含我」。

用户端从屏幕宽度 360px 起可以完成查询。

### 4.1 打开「项目」

**操作：** 打开用户端首页。

**页面：「项目」标签**

「项目」高亮。页面展示：

- 状态用按钮平铺，选项为「全部」「进行中」「已完成」「已关闭」，同一时间只选中一项。改完名称或状态即查。

| 打开某一行 | 该项目的项目详情，「项目」仍高亮 |
| 「善款」 | 「善款」标签，见 4.4 |
| 「我的」 | 「我的」的用户登录，见 4.5 |

页面不展示：受益人姓名和唯一 ID、善款备注、平台用户 ID、订单编号、身份手机号、已作废开销、已解除绑定、管理操作按钮。已删除的进展不在此页。

| 可操作选项 | 操作后的页面 |

### 4.3 查看「善款」

**操作：** 在项目详情中查看「善款」。这一段在「进展」后面、「开销」前面。

**页面内容（项目详情中的这一块）：**

只包含绑定到本项目、且绑定仍然有效的未作废善款，按捐款日期倒序。不按平台或日期筛选，也不分页。默认只展示前 5 条。多于 5 条时，下方居中显示「查看更多善款」，每点一次再展示 5 条。已经多看过、且仍有未展示记录时，「收起更多善款」与「查看更多善款」并排，收起在左。全部展示后只留下「收起更多善款」，点它回到前 5 条。每一笔与第 4.4 节同一张卡片，但不展示「已绑定」标签。人已经在这个项目里，不再重复项目名称。

没有有效绑定时，这块显示「帮助来源待补充」。

匿名为「匿名捐款人」的行不出现对外展示名。本段不展示个人说明。

- 其下：金额、平台

| 「项目」 | 「项目」列表 |

- 手机号

- 页面底部居中的可操作文字「重置密码」，没有边框

### 4.6 未登录用户走完公开信息的一条路径

2. 筛选「进行中」，列表只剩进行中的项目。
3. 打开一个项目，看到简介、结余，以及按进展、善款、开销排列的三段。项目没有封面。
4. 若还没有有效绑定，「善款」显示「帮助来源待补充」。
5. 点「善款」，未绑定的行显示「尚未安排到具体项目」；已绑定的行可以点进项目。
6. 匿名捐款只显示「匿名捐款人」。未匿名捐款只显示公开称呼，不展示个人说明。
7. 点「我的」，看到用户登录。未登录时没有「进入后台」。

## 5. 登录用户

登录用户是捐款人、受益人，或两者都是。用户端不需要预先录入手机号。第一次验证通过就建立个人空间。

登录后三个标签仍在。「项目」和「善款」的公开内容见第 4 章，多出来的标记见 5.11。本章写「我的」标签。

登录成功后停在「我的」。这一页从上到下是：

| 区域 | 内容 |
| --- | --- |
| 页头 | 脱敏登录手机号和退出并排靠右，不换行。登录手机号是启用管理员时，「进入后台」在最右 |
| 我的捐赠身份列表 | 当前手机号已认领的捐赠身份。打开一条进入该身份的捐款列表 |
| 绑定捐赠身份 | 用平台和平台用户 ID 再认领一条身份 |
| 我的受益 | 已绑定后，姓名和脱敏号码在包含自己的项目上方，不再显示「绑定受益人身份」；未绑定只说明绑定后才会列出项目，并给出「绑定受益人身份」 |

一个登录手机号可以同时认领多条捐赠身份，并且绑定一名受益人。

### 5.1 在「我的」登录或重置密码

**操作：** 未登录时点「我的」。页面默认是密码登录。

**页面：「我的」中的用户登录**

「我的」高亮。「项目」和「善款」仍可切换。这一页只有用户登录，没有「管理员」，也不显示「登录」标题。登录内容上下居中，「重置密码」在页面底部。

| 输入 | 页面要求 |
| --- | --- |
| 手机号 | 11 位中国大陆手机号 |
| 密码 | 密码登录时填写。至少 8 位。输入手机号后，密码提示紧挨在「密码」右侧、输入框上方，不靠行尾 |
| 验证码 | 验证码登录时填写。短信中的验证码 |

点「验证码登录」标签后出现获取验证码。发送成功时说明验证码已发送，5 分钟内有效。同一手机号 1 小时内已经发送 5 次时，本次不再发送，并说明已达到上限。任意手机号都可以收到验证码。是否管理员不影响这次发送。

**操作：** 填写后点「登录」。

| 结果 | 操作后的页面 |
| --- | --- |
| 密码正确，或验证码正确且未过期 | 仍在「我的」。登录表单消失，页内换成上面的四块内容，并完成本次自动认领。手机号是启用管理员时，页头出现「进入后台」 |
| 尚未设置密码，或密码不正确 | 仍停在密码登录，说明密码不正确或尚未设置，可改用验证码登录或重置密码 |
| 验证码错误或已超过 5 分钟 | 仍停在验证码登录，说明验证码不正确或已失效，可以重新获取（仍受 1 小时 5 次限制） |
| 登录态之后过期，再点「我的」 | 回到用户登录，默认仍是密码登录。重新登录时，已经认领过的身份不会重复认领 |

**操作：** 在登录页点「重置密码」。

**页面：重置密码**

返回在左上，回到登录页。页面有手机号、获取验证码、验证码、新密码、确认新密码、密码提示。「确认重置」在最右。「非必填」紧挨在「密码提示」右侧，不靠行尾，可以不填。填写后，下次用该手机号做密码登录时紧挨在「密码」右侧，不靠行尾；留空则不显示。留空不影响重置。

| 结果 | 操作后的页面 |
| --- | --- |
| 验证码正确，新密码至少 8 位，且两次一致 | 登录页，说明密码已重置，请用新密码登录。页面仍默认密码登录。密码提示按这次填写的内容更新，留空则不再显示 |
| 验证码错误或过期、密码不足 8 位，或两次不一致 | 停在重置密码，并说明原因 |
| 返回 | 登录页，密码不变 |

第一次验证码登录通过时建立个人空间。之后用同一手机号以密码或验证码登录，回到原来的个人空间。

### 5.2 登录后看到「我的」

登录成功的同一时刻，系统查找「捐款身份上的手机号 = 本次登录手机号」，并且当前登录还没有认领过的身份，自动建立认领。一次登录可以认领多条。已经认领的不重复建立。

自动认领不包含这些身份：

- 身份手机号为空
- 身份手机号与本次登录手机号不同
- 当前手机号已经认领过该身份
- 身份下的善款已全部作废（这些善款本来就不会出现在捐赠身份里）

受益人不会在登录时自动绑定。「包含我」要等手动绑定姓名和唯一 ID 成功后才出现。

**页面：「我的」**

「我的」高亮。登录表单已经不在。页头是脱敏登录手机号和「退出」并排靠右，不换行。登录手机号是启用管理员时，「进入后台」在最右。其下四块都在同一页。

有匹配身份时，认领结果直接出现在捐赠身份列表里，不另计已认领身份数。身份见 5.3，某一身份下的善款见 5.4。

没有匹配身份时，捐赠身份列表显示：

- 累计捐款金额、已进入项目的金额、尚未安排的金额都是 0
- 说明当前没有已认领的捐赠身份

尚未绑定受益人时，「绑定受益人身份」在项目说明上方。说明绑定后才会列出包含自己的项目。这个空状态不代替「项目」标签里的公开列表。

| 可操作选项 | 何时出现 | 操作后的页面 |
| --- | --- | --- |
| 查看捐赠身份列表 | 始终可以。没有认领时是空状态 | 仍在「我的」，内容见 5.3 |
| 绑定捐赠身份 | 始终可以，居中的可操作文字。没有认领时也在捐赠身份下方 | 仍在「我的」，展开绑定表单，见 5.5 |
| 绑定受益人身份 | 尚未绑定时可以展开。表单见 5.8。绑定成功后隐藏 | 仍在「我的」 |
| 查看包含自己的项目 | 已绑定受益人 | 仍在「我的」，列表见 5.9 |
| 退出 | 始终可以 | 见 5.12 |
| 进入后台 | 仅当登录手机号是启用管理员 | 项目列表，见 3.1。管理端接口校验当前登录手机号 |
| 「项目」或「善款」 | 始终可以 | 对应标签，并带上第 5.11 节的标记 |

### 5.3 查看我的捐赠身份列表

**页面：「我的」中的「我的捐赠身份列表」**

这块在「我的」页上，不是另一个标签。身份已经逐条列出，不再统计已认领身份数。金额汇总：

- 累计捐款金额：已认领身份下全部未作废善款之和
- 已进入项目的金额：其中已有有效项目绑定的金额
- 尚未安排的金额：未绑定且未作废的金额

其下按捐款身份列出。每张卡片同一行：捐赠身份名称、匿名或不匿名、捐赠平台。操作靠右：解除绑定、修改对外资料、打开。这一层不展开每一笔善款。已作废善款不计入，也不单独出现。平台用户 ID 和善款备注不在本页。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 滑到列表底部 | 仍在「我的」，捐赠身份接上下一页，直到全部加载完。底部不显示「共 N 条」 |
| 打开一条身份 | 该身份的捐款列表，见 5.4 |
| 修改对外资料 | 修改身份。修改的是这一整条身份，名下每一笔都使用保存后的资料。保存或取消后回到「我的」 |
| 解除绑定 | 先弹出确认。确认后仍在「我的」，这一身份从列表中消失，金额汇总重算。取消则不解除 |
| 绑定捐赠身份 | 仍在「我的」，展开绑定表单，见 5.5 |
| 「项目」或「善款」 | 对应标签 |

解除绑定只影响当前登录手机号。身份、其他手机号的认领、善款本身、项目绑定都还在。

若解除后一个身份都不剩，捐赠身份列表回到 5.2 的空状态，「绑定捐赠身份」仍在。

### 5.4 查看捐款列表

**操作：** 在捐赠身份列表中打开一条身份。

**页面：捐款列表**

「我的」仍高亮。顶部展示这条捐赠身份：公开称呼在左，是否匿名紧跟名称，平台在下方。其下每一笔未作废善款一张卡片，只显示捐款金额、绑定状态、捐款日期和绑定项目。已绑定时项目名称可进入项目公开页；未绑定时为「尚未安排到具体项目」。绑定状态用按钮平铺，选项为「全部」「已绑定」「未绑定」，同一时间只选中一项，改完即查。捐款日期不作为查询条件展示。

卡片上不展示公开称呼和个人说明。不展示管理备注，不展示平台用户 ID 和订单编号。本页没有修改对外资料、解除绑定、作废和改金额。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 修改绑定状态 | 改完立即查询，仍是捐款列表第 1 页。改回「全部」时恢复该身份下全部未作废善款 |
| 滑到列表底部 | 仍是捐款列表，接上下一页，直到全部加载完。条件不变。总数在底部 |
| 进入项目 | 仅已绑定的行出现。打开该项目公开详情，「项目」高亮。自己的善款行上有「我的捐款」 |
| 「尚未安排到具体项目」 | 说明文字，不能点进项目 |
| 返回「我的」 | 「我的」。捐赠身份列表、绑定入口和我的受益都还在 |

### 5.5 绑定捐赠身份

**操作：** 在「我的」点击「绑定捐赠身份」。没有单独页面。

**页面：「我的」**

「我的」仍高亮，不进入新页面。文字变为「收起绑定捐赠身份」，其下展开两个输入项：

- 平台：微信支付或支付宝
- 平台用户 ID：去掉首尾空格后精确匹配，区分大小写，最长 64 个字符

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 提交绑定 | 按下面三种结果之一继续，标签仍是「我的」 |
| 收起绑定捐赠身份 | 仍在「我的」，表单收起，文字变回「绑定捐赠身份」 |

**结果一：找到身份，且至少有一笔未作废善款，当前手机号尚未认领**

**页面：「我的」**

提交后仍在「我的」，表单收起，文字变回「绑定捐赠身份」。该身份出现在捐赠身份中，汇总重算。不展示笔数和金额合计。多个手机号可以绑定同一身份，看到的是同一条身份和同样的善款。

**结果二：没有匹配身份，或匹配到的身份没有未作废善款**

**页面：「我的」，绑定表单仍展开**

页面提示「未找到对应捐款记录」。不保留认领。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 修改平台或平台用户 ID 后再次提交绑定 | 重新进入上面的三种结果之一 |
| 收起绑定捐赠身份 | 仍在「我的」，表单收起，认领数量不变 |

**结果三：当前手机号已经认领该身份**

**页面：「我的」，绑定表单仍展开**

页面提示已经绑定。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 收起绑定捐赠身份 | 仍在「我的」，表单收起，原有认领还在 |
| 改用另一组平台和平台用户 ID 再提交绑定 | 按新的输入重新得到结果一或结果二 |

### 5.6 修改已认领身份的对外资料

**操作：** 在「我的」的捐赠身份列表里，对某一身份点击「修改对外资料」。

**页面：修改身份**

「我的」仍高亮。可以修改匿名、对外展示名和个人说明。手机号只展示：

| 字段 | 页面上的约束 |
| --- | --- |
| 是否匿名 | 是或否 |
| 对外展示名 | 可空。未匿名时，公开页面用它作为称呼；为空时公开页面用「{平台}捐款人」 |
| 个人说明 | 可空，不超过 200 字。用户端善款列表和项目详情的善款不展示 |
| 手机号 | 只读。捐款人不能修改，也不能清空。批量导入有值时仍会更新 |

平台、平台用户 ID 和手机号都显示为不可修改的文字。

保存匿名、对外展示名或个人说明中的任意一项后，这条身份变为「用户已修改」，并记下修改时间。多个登录手机号认领同一身份时，任意一个手机号保存都会加上标记。捐款人之后仍可继续修改这三项。管理人员随时可以更正这三项，保存后标记改回「未修改」，修改时间清空。管理人员的单笔录入不修改这三项。标记为已修改期间，导入不再覆盖这三项；管理人员改回未修改后，导入又可覆盖展示名。手机号不受这个标记限制，导入有值时仍会更新。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 保存 | 回到「我的」。捐赠身份列表里这条身份已是新内容 |
| 取消 | 回到「我的」，资料不变 |

个人说明超过 200 字时，停在修改身份，说明超出长度，不保存。手机号没有可编辑的输入，也就没有格式校验。

### 5.7 解除绑定

**操作：** 在捐赠身份列表的某一身份上点击「解除绑定」。页面弹出确认，说明解除只影响当前手机号。点「确认解除」后才解除；点「取消」则留在「我的」，认领不变。

**页面：「我的」**

- 当前手机号的捐赠身份里不再显示该身份及其善款。
- 汇总按剩下的认领重算。
- 另一个已经认领同一身份的手机号，打开「我的」后仍然看得到这些善款。
- 「善款」标签里，这些未作废善款仍在。项目上的有效绑定仍在。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 再次绑定同一身份 | 「我的」里再次提交绑定后，该身份重新出现在捐赠身份中 |
| 继续查看其他已认领身份 | 仍在「我的」 |

### 5.8 绑定受益人身份

**操作：** 在「我的」点击「绑定受益人身份」。

**页面：「我的」中的「我的受益」**

「我的」仍高亮，不进入新页面。文字变为「收起绑定受益人身份」，其下展开两个输入项：

| 字段 | 要求 |
| --- | --- |
| 姓名 | 必填，去掉首尾空格后与档案一致 |
| 唯一 ID | 必填，去掉首尾空格后与档案一致。推荐填写身份证号 |

尚未绑定时，「绑定受益人身份」在项目说明上方。标题下只说明绑定后才会列出包含自己的项目，不展示项目。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 提交绑定 | 按下面三种结果之一继续，仍在「我的」 |
| 收起绑定受益人身份 | 仍在「我的」，表单收起，文字变回「绑定受益人身份」 |
| 「项目」 | 「项目」列表。这块的空状态不代替公开项目 |
| 「善款」 | 「善款」标签 |

**结果一：姓名和唯一 ID 与档案一致，当前手机号尚未绑定受益人**

提交后仍在「我的」，表单收起，「绑定受益人身份」隐藏。包含自己的项目列在「我的受益」下，姓名和脱敏号码出现在项目列表上方。见 5.9。

**结果二：不一致或档案不存在**

表单保持展开，提示「未找到匹配的受益人信息」，不说明是姓名不对还是唯一 ID 不对，也不建立绑定。

**结果三：当前手机号已经绑定受益人**

本页不再显示「绑定受益人身份」。要换成另一名受益人，先解除，再提交另一组姓名和唯一 ID。

### 5.9 绑定成功后查看我的受益

**操作：** 姓名和唯一 ID 与档案一致，在「我的」提交绑定。

**页面：「我的」**

「我的受益」更新为：

- 当前绑定的受益人姓名和脱敏号码并排在项目列表上方，不显示「唯一 ID」字样。点击号码后看完整值。解除绑定靠右。只显示自己的，不显示其他受益人。不再显示「绑定受益人身份」。
- 包含自己的项目直接列在姓名下方，不另写「受益项目」，不另开页面，也不按名称或状态筛选。滑到底继续加载，默认按开始日期倒序，底部不显示「共 N 条」。最后一条下方不画线。每一条与第 4.1 节同一三行，名称后只有状态标签。简介在打开后的项目详情里看。
- 没有此类项目时，说明「暂时没有包含我的项目」。「项目」标签里的公开列表仍可查看。

一名受益人可以在多个项目里。受益人尚未登录时，管理人员先把档案加入项目也有效；绑定成功后，项目立刻列出。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 打开本页上的一条项目 | 项目公开详情，「项目」高亮，页上有「包含我」，见 5.10 |
| 从项目详情返回 | 「我的」。项目列表仍在「我的受益」下 |
| 解除受益人绑定 | 「我的」不再列出这些项目，回到未绑定说明。「绑定受益人身份」重新出现并保持收起。该手机号不再显示「包含我」。档案、项目，以及其他手机号上的绑定都保留 |
| 「项目」 | 全部公开项目的列表。自己所在的项目打开后带「包含我」 |
| 「善款」 | 「善款」标签 |

一个手机号同时只能绑定一个受益人档案。绑定成功后不再显示「绑定受益人身份」。要换成另一名受益人，先解除，再提交另一组姓名和唯一 ID。

两个手机号可以绑定同一个档案。两边的「我的」都看得到同一批项目，也都看不到对方或其他受益人的姓名。

### 5.10 打开包含自己的项目

**操作：** 从「我的」本页包含自己的项目，或从「项目」打开自己所在的项目。

**页面：项目详情**

「项目」高亮。公开内容与第 4.2、4.3 节相同。「包含我」紧跟在受益人人数后面。

仍然看不到：其他受益人姓名、唯一 ID、受益人备注、善款备注、平台用户 ID、订单编号、身份手机号。

若这个项目里也有当前手机号认领过的善款，「善款」里那些行同时带「我的捐款」。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 返回 | 从「我的」进入的，回到「我的」；从「项目」进入的，回到「项目」列表 |
| 「善款」 | 「善款」标签 |
| 「我的」 | 「我的」 |

### 5.11 登录后再次浏览「项目」和「善款」

登录不改变公开字段，只在原有内容上增加标记。包含自己的项目直接列在「我的受益」下，不在「项目」标签上再做一层筛选，也不另开列表页。

**「项目」**

- 列表字段与未登录时相同。
- 打开自己所在的项目后，详情显示「包含我」。
- 不在这个项目中时，详情不显示「包含我」。

**善款**

- 某一行属于当前手机号已认领的捐赠身份：该行显示「我的捐款」。
- 其他行与未登录时相同。

**「善款」**

- 字段与未登录时相同，仍按公开称呼展示。
- 查看自己的金额、匿名状态、展示名和个人说明，回到「我的」的捐赠身份列表，再进入该身份的捐款列表。

### 5.12 退出登录

**操作：** 在「我的」页头点击「退出」。

**页面：「项目」**

页头在退出前展示当前登录手机号的脱敏值（前 3 位和后 4 位）。退出后：

- 回到首页「项目」，恢复为未登录状态。
- 再点「我的」，看到 4.5 的用户登录。未登录时没有「进入后台」。
- 「项目」和「善款」仍可查看。
- 认领和受益人绑定都还在，下次用同一手机号登录后会再出现在「我的」。

### 5.13 同一个人既捐款又受助

**操作：** 用同一个手机号在「我的」完成登录。

登录成功后，「我的」同一页上有两件独立的事：

1. 捐赠身份由自动认领处理。没有匹配手机号时，使用 5.5 绑定捐赠身份。
2. 受益人尚未绑定时，点「绑定受益人身份」才展开表单。绑定成功后，包含自己的项目直接列在「我的受益」下。

两件事可以只做一件。只认领捐赠身份时，项目详情的「善款」上有「我的捐款」，项目详情没有「包含我」。只绑定受益人时，项目详情有「包含我」，捐赠身份仍是空状态和「绑定捐赠身份」。

## 6. 跨角色串联

下面三条路径把三种角色连在一起。每一步都对应前面的页面。

### 6.1 录入、认领、绑定到项目

1. 技术人员已在数据库中放好至少一名启用管理员。
2. 管理员打开用户端「我的」，用预先录入的手机号完成用户登录。页头出现「进入后台」。点击后直接进入项目列表。
3. 管理员打开受益人列表，新建受益人，填写姓名、唯一 ID、备注，进入受益人详情。
4. 在受益人详情点击「创建项目」。该受益人已经添加且不能移除。填写名称、简介、开始日期后保存。项目详情为进行中，三项金额为 0。
5. 未登录用户打开首页「项目」，能看到这个项目，受益人只有人数，「善款」为「帮助来源待补充」。
6. 管理员打开捐款身份列表，创建一条微信支付身份，匿名为「是」，可以不填手机号。保存后进入身份详情，名下还没有善款。再到善款列表单笔录入，按平台用户 ID 查询并添加这条身份，填写金额、日期和订单编号。保存后回到善款列表，这笔为未绑定。身份资料仍是创建时的内容。
7. 未登录用户点「善款」，看到这条记录，称呼为「匿名捐款人」，项目列为「尚未安排到具体项目」。
8. 知道平台和平台用户 ID 的捐款人，点「我的」，用自己的手机号登录。若录入时没有手机号，捐赠身份为空，页上有「绑定捐赠身份」。
9. 捐款人填写平台和平台用户 ID，提交绑定后仍在「我的」，捐赠身份列表里出现该身份。打开后，捐款列表里这笔的状态为未绑定。
10. 另一个手机号按同样步骤绑定同一身份，也能看到同一笔。先绑定的手机号仍然看得到。
11. 管理员在刚创建的项目详情点击「绑定善款」，确认这笔。项目详情的善款合计等于这笔全额，结余同步增加。善款列表中这笔变为已绑定。
12. 未登录用户重新打开项目详情，「善款」出现这条匿名捐款，「帮助来源待补充」消失。
13. 捐款人打开「我的」，再打开该身份的捐款列表，这笔的项目列变成项目名称；进入项目后，自己的那一行带「我的捐款」。

### 6.2 覆盖展示资料，以及用户修改后展示资料不再覆盖

1. 管理员创建一条捐款身份，匿名为「是」。此时还没有善款，用户已修改为否。
2. 单笔录入查询并添加该身份，新增一笔未绑定善款。身份仍是匿名。
3. 用户尚未修改时，管理员在身份详情改为不匿名，展示名「张三」，个人说明「希望用于助学」。保存后不新增善款，标记仍是用户未修改。公开称呼变为「张三」。用户端善款页和项目详情的善款不展示个人说明。这笔善款使用这套当前资料。
4. 捐款人认领后，在修改身份里把展示名改成「张先生」并保存。身份变为用户已修改。手机号在这一页是只读的。
5. 管理员再次单笔录入只新增善款，不改身份资料。标记仍为用户已修改时再次导入，展示名不覆盖；导入行有手机号则身份手机号更新为该值，留空则不改变。写入后只多一笔善款，公开称呼仍是「张先生」。
6. 管理员在身份详情把展示名更正为「张老师」并保存。标记改回用户未修改，修改时间清空。之后导入又可覆盖展示名。

### 6.3 导入两个平台、项目结余和受益人

1. 管理员按模板准备两行：一行微信支付、一行支付宝，手机号都填同一个 11 位号码，金额和日期合法。导入预览标明将新建两个身份，手机号将写入。确认写入。
2. 该手机号在「我的」登录后，捐赠身份列表里同时出现两个身份。各自的捐款列表里是对应的未作废善款。
3. 若另一行手机号留空，该身份不会因为同批其他行而自动认领。手机号格式错误时，预览标出该行行号和原因，整批都不写入。
4. 管理员在项目 A 的详情把两笔都绑定过去。已绑定的不再出现在其他项目的可绑定名单里。要改绑就先解除。
5. 管理员解除其中一笔。项目 A 的善款合计减少。再把这笔绑到项目 B，B 的合计增加，A 不再包含它。已完成、已关闭的项目同样可以完成这次绑定。
6. 管理员在项目上登记一笔大于结余的开销。保存成功，详情标记「超支」。管理端项目列表在状态后面显示「超支」，筛选「超支」时能看到它。用户侧「项目」列表只显示状态，不显示「超支」。
7. 受益人用手机号在「我的」登录。点「绑定受益人身份」，提交与档案一致的姓名和唯一 ID 后，包含自己的项目按公开项目列表的三行直接列在「我的受益」下，名称后只有状态标签，不另开页面。打开项目后显示「包含我」，看不到其他受益人。简介在项目详情里。
8. 该手机号绑定成功后不再显示「绑定受益人身份」。另一个手机号可以绑定同一档案，并在自己的「我的」里看到同一批项目。
9. 新手机号没有任何捐赠身份、也还没绑定受益人时，在「我的」登录：捐赠身份给出「绑定捐赠身份」，我的受益给出「绑定受益人身份」。切到「项目」仍可浏览全部公开项目。
