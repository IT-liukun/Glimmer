# 微光用户用例手册

| 项 | 内容 |
| --- | --- |
| 产品名称 | 微光 |
| 手册版本 | V1.0 |
| 依据文档 | 《微光产品需求文档》V1.0（2026-10-16） |
| 读者 | 管理人员、捐款人、受益人、测试、实施 |
| 本期范围 | 单机构。工作台、项目进展为 P1，本期一并交付 |

本手册按真实使用顺序写。每一步都说明：做完之后停在哪个页面、页面上有什么、接下来可以点什么、点完又到哪里。

管理端和用户端分开。管理人员在管理端记账、立项；捐款人和受益人在用户端查看和认领。同一个人可以既是捐款人又是受益人，用同一个手机号登录用户端即可。管理人员若也要认领自己的捐款或绑定受益人，使用用户端的「我的」标签，不在管理端做这两件事。

用户端首页有三个标签：「项目」「善款」「我的」。打开首页时停在「项目」。三个标签在列表、详情和登录过程中一直显示，当前标签高亮。

## 1. 三种使用方式

| 使用方式 | 怎么进入 | 打开后首先看到 | 本手册章节 |
| --- | --- | --- | --- |
| 管理员 | 先在「我的」完成用户登录。手机号已预先录入并处于启用时，页头出现「管理员」，点击后进入工作台 | 工作台 | 第 3 章 |
| 未登录用户 | 直接打开用户端首页 | 「项目」标签 | 第 4 章 |
| 登录用户 | 在「我的」用任意手机号 + 短信验证码 | 「我的」标签 | 第 5 章 |

全系统没有用户名、密码、注册和找回密码，也没有单独的管理员登录。验证码 5 分钟内有效，同一手机号 1 小时内最多发送 5 次。登录态过期后重新验证。退出登录清除本机登录态。管理端接口另校验当前登录手机号是否为启用管理员，这次校验不发送验证码。

金额在服务端按人民币计算，必须大于 0，最多两位小数。

编号规则：

| 对象 | 编号 |
| --- | --- |
| 善款 | `SK` + 年月日 + 4 位当日流水 |
| 项目 | `XM` + 年月日 + 4 位当日流水 |
| 开销 | `KX` + 年月日 + 4 位当日流水 |
| 项目进展 | `JZ` + 年月日 + 4 位当日流水 |

手机号、受益人唯一 ID 在页面上默认保留前 3 位和后 4 位，例如 `138****0000`。管理端的身份手机号、受益人唯一 ID 可以点击后再看完整值。管理端台账直接展示完整平台用户 ID。用户端「我的」页头展示脱敏后的登录手机号。

公开称呼：

| 身份情况 | 公开页面上的称呼 | 个人说明 |
| --- | --- | --- |
| 匿名 | 匿名捐款人 | 不展示 |
| 未匿名，对外展示名有内容 | 对外展示名原文 | 有内容时可展开 |
| 未匿名，对外展示名为空 | `{平台}捐款人`，例如「微信支付捐款人」 | 有内容时可展开 |

已作废善款、已解除的善款绑定、已作废开销、已撤回进展，不出现在公开页面。

平台首期只有两项：微信支付、支付宝。录入、导入、手动绑定使用同一份清单。

## 3. 管理员

管理员使用管理端。手机号由技术人员预先写入数据库，状态为启用或停用。手机号在管理员中唯一。系统初始化时至少有一名启用管理员。新增和停用在数据库中完成，管理端名单只读。停用后仍可使用用户登录，但不能调用管理端接口，并且必须始终保留至少一名启用管理员。

捐款人和受益人不能进入管理端。管理员不在用户端做录入、导入、绑定项目、登记开销这些台账操作。

管理端支持最近两个版本的 Chrome、Edge。

管理端登录后的固定入口：

| 入口 | 页面 |
| --- | --- |
| 工作台 | 登录后的首页（P1） |
| 善款 | 善款列表 |
| 项目 | 项目列表 |
| 受益人 | 受益人列表 |
| 管理员 | 管理员名单 |

### 3.1 进入工作台

**操作：** 先在「我的」用手机号和短信验证码完成用户登录。登录手机号是启用中的管理员时，「我的」页头出现「管理员」。点击「管理员」。

未登录时没有「管理员」。登录手机号未录入，或管理员已停用时，页头也没有「管理员」。

**页面：工作台**

离开用户端，进入工作台，见 3.2。

管理端每个接口都校验这次请求里的当前登录手机号：登录态仍然有效，且该手机号是启用中的管理员。这次校验不发送验证码。未登录、手机号未录入或已停用时，接口拒绝，不返回台账。若点击时已经停用，留在「我的」，页头不再显示「管理员」，并提示「该手机号没有管理权限」。

没有账号、密码、注册和管理员自助添加。

### 3.2 查看工作台（P1）

**页面：工作台**

三块数字：

| 数字 | 含义 |
| --- | --- |
| 未绑定善款笔数与金额 | 未作废、且没有有效项目绑定的善款 |
| 进行中的项目数 | 状态为进行中的项目 |
| 超支项目数 | 结余小于 0 的项目，不限项目状态 |

某一项为 0 时，数字显示 0，仍可点击。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 未绑定善款 | 善款列表，筛选为「未绑定」，并看到这些善款的笔数与金额 |
| 进行中的项目 | 项目列表，筛选为「进行中」 |
| 超支项目 | 项目列表，只保留结余小于 0 的项目 |
| 善款 / 项目 / 受益人 / 管理员 | 对应列表，不带工作台筛选 |

### 3.3 查看善款列表

**页面：善款列表**

默认按捐款日期倒序。每一行：

- 善款编号
- 平台
- 平台用户 ID（完整）
- 身份手机号（脱敏）
- 当前展示名
- 当前是否匿名
- 金额
- 捐款日期
- 绑定状态：未绑定、已绑定、已作废
- 已绑定项目：有有效绑定时为项目名称

展示名、是否匿名显示的是身份当前值。同一身份下的每一笔都跟着身份现在的资料变，不保留录入那一刻的旧副本。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 按平台筛选 | 仍是善款列表 |
| 按平台用户 ID 筛选 | 仍是善款列表，精确查找该身份键中的 ID |
| 按手机号筛选 | 仍是善款列表 |
| 按绑定状态筛选：未绑定、已绑定、已作废 | 仍是善款列表 |
| 按捐款日期筛选 | 仍是善款列表，结果继续按捐款日期倒序 |
| 清除筛选 | 全部善款 |
| 点击脱敏手机号 | 仍是本行，展开完整手机号 |
| 打开一行 | 善款详情 |
| 新建善款 | 单笔录入 |
| 批量导入 | 导入预览的文件选择 |
| 返回工作台 | 工作台 |

### 3.4 单笔录入善款

**操作：** 在善款列表点击「新建善款」。

**页面：单笔录入**

| 字段 | 页面要求 |
| --- | --- |
| 平台 | 必填。微信支付或支付宝。创建后不能改 |
| 平台用户 ID | 必填，最长 64 个字符。创建后不能改 |
| 是否匿名 | 必填，默认「是」 |
| 对外展示名 | 选填 |
| 个人说明 | 选填，不超过 200 字 |
| 金额 | 必填，大于 0，最多两位小数 |
| 捐款日期 | 必填，格式 `YYYY-MM-DD`，不得晚于录入当天 |
| 备注 | 选填。只有管理人员可见 |

本页没有手机号。单笔录入不修改身份上的手机号。页面写明：身份手机号由批量导入或捐款人本人维护。

填写平台和平台用户 ID 之后、保存之前，若该身份已经存在，表单上先出现说明：

| 身份现状 | 保存前的说明 |
| --- | --- |
| 不存在 | 将新建一条捐款身份，并新增一笔未绑定善款 |
| 已存在，用户未修改 | 本次会覆盖是否匿名、对外展示名、个人说明。展示名或个人说明留空也会覆盖成空。不修改手机号。同时新增一笔未绑定善款 |
| 已存在，用户已修改 | 本次不覆盖是否匿名、对外展示名、个人说明，也不修改手机号。只新增一笔未绑定善款 |

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 保存 | 校验通过后进入新善款的详情。状态为未绑定，编号形如 `SK202610130001` |
| 取消 | 善款列表，不产生身份，也不产生善款 |

校验不通过时停在单笔录入，并说明原因，例如：平台不在清单中、平台用户 ID 为空或超过 64 个字符、金额不大于 0 或超过两位小数、日期格式不对或晚于今天、个人说明超过 200 字。

保存成功后的数据结果：

1. 身份不存在：创建身份，「用户已修改」为否，写入这次的匿名、展示名、个人说明，再新增一笔未绑定善款。
2. 身份已存在且用户未修改：用这次的三项覆盖身份，再新增一笔未绑定善款。
3. 身份已存在且用户已修改：三项保持用户保存的内容，再新增一笔未绑定善款。

### 3.5 预览并导入善款

**操作：** 在善款列表点击「批量导入」。

**页面：选择导入文件**

模板列为：

```text
平台,平台用户ID,对外展示名,手机号,金额,捐款日期
微信支付,oAbc123,张三,13800000000,200,2026-10-01
支付宝,2088xxxx,,13900000000,500.50,2026-10-02
```

文件中不包含是否匿名、个人说明、备注。单次最多 500 行。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 上传文件并预览 | 导入预览 |
| 取消 | 善款列表 |

**页面：导入预览**

每一行都标出将要发生的事，或标出错误。超过 500 行时不进入逐行写入，页面说明超出单次上限。

校验规则：

- 平台必须在清单内
- 平台用户 ID 非空且不超过 64 个字符
- 手机号为空，或为 11 位中国大陆手机号
- 金额大于 0 且最多两位小数
- 日期为 `YYYY-MM-DD`，且不晚于当天

身份处理在预览中这样标明：

| 这一行对应的身份 | 预览文字 |
| --- | --- |
| 还不存在 | 将新建身份：匿名为「是」，个人说明为空，「用户已修改」为否。展示名用本行内容。手机号有值则写入。并新增一笔未绑定善款，备注为空 |
| 已存在，用户未修改 | 「展示名将更新」。手机号有值时标明「手机号将写入」；手机号留空时标明「手机号因留空不改变」。匿名和个人说明不改 |
| 已存在，用户已修改 | 「展示名本次不覆盖」「手机号本次不覆盖」。匿名、个人说明也不改 |

同一身份在这一批里有多行时，预览另外写明：每一行各生成一笔善款；若用户未修改，展示名以最后一行为准，手机号以最后一条非空手机号为准。

| 可操作选项 | 何时可点 | 操作后的页面 |
| --- | --- | --- |
| 确认写入 | 全部行都通过 | 导入结果 |
| 返回修改文件 | 始终可以 | 选择导入文件。本次没有写入 |
| 确认写入 | 任意一行失败 | 按钮不可用。页面列出每一个失败行的行号和原因 |

**页面：导入结果（全部成功）**

页面说明本批已写入的行数和新增善款笔数。任一行失败时不会到达这个成功页，而是停在预览，整批都不写入。

若本次写入了手机号，或更新了手机号，结果页说明：该号码已经有登录身份的，会立即出现在对应用户「我的」标签的捐赠身份里；还没有登录过的，等下次用该号码登录再认领。旧认领保留。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 前往善款列表 | 善款列表。新善款为未绑定，按各自捐款日期排进列表 |
| 再导入一批 | 选择导入文件 |

### 3.6 查看善款详情并按状态操作

**操作：** 在善款列表打开一条。

**页面：善款详情**

页面展示：

- 善款编号、金额、捐款日期、绑定状态
- 备注（含历史备注；若已作废，原因在备注末尾）
- 所属身份：平台、平台用户 ID、当前是否匿名、当前展示名、当前个人说明
- 身份手机号：默认脱敏，点击后显示完整号码
- 「用户已修改」以及修改时间（尚未修改时，标记为否，没有修改时间）
- 当前项目：有有效绑定时为项目名称；没有时说明尚未绑定
- 已解除的绑定记录：曾经绑定过时列出项目、金额、状态「已解除」。这些记录不计入项目合计

| 状态 | 页面上可做的操作 | 操作后的页面 |
| --- | --- | --- |
| 未绑定 | 更正金额和日期 | 更正善款 |
| 未绑定 | 作废 | 作废善款 |
| 未绑定 | 绑定到项目 | 选择项目 |
| 未绑定 | 打开身份 | 身份详情 |
| 已绑定 | 解除绑定 | 确认后仍是本详情：状态变为未绑定，当前项目清空，原绑定变为已解除，项目善款合计和结余重算 |
| 已绑定 | 更正金额和日期 | 停在本页，说明需先解除绑定 |
| 已绑定 | 作废 | 停在本页，说明只有未绑定善款可以作废 |
| 已绑定 | 打开当前项目 | 项目详情 |
| 已绑定 | 打开身份 | 身份详情 |
| 已作废 | 打开身份 | 身份详情 |
| 已作废 | 返回列表 | 善款列表 |
| 任意 | 返回善款列表 | 善款列表 |

已作废的详情上，金额、日期、绑定、再次作废都不可用。平台和平台用户 ID 在任何状态下都不能直接改成另一个身份。录错时：若这笔还没绑定，作废它，再用正确的平台和平台用户 ID 重新单笔录入；若已经绑定，先解除，再作废，然后重新录入。

### 3.7 更正金额和日期

**操作：** 在未绑定的善款详情点击「更正金额和日期」。

**页面：更正善款**

可修改金额、捐款日期。编号、平台、平台用户 ID、备注、匿名和展示资料不在本页修改。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 保存 | 善款详情。金额和日期已更新，状态仍是未绑定 |
| 取消 | 善款详情，原金额和日期不变 |

金额不大于 0、超过两位小数、日期晚于今天或格式不对时，停在更正善款并说明原因。

已绑定善款要改金额时的连续页面：

1. 善款详情提示先解除绑定。
2. 解除后，详情变为未绑定，项目合计已减去这笔全额。
3. 进入更正善款，保存新金额和日期。
4. 再从详情进入选择项目，重新绑定。项目按新金额计入善款合计和结余。

### 3.8 作废未绑定善款

**操作：** 在未绑定的善款详情点击「作废」。

**页面：作废善款**

页面要求填写作废原因。没有单独的「作废原因」字段，原因会追加到备注末尾，原备注保留。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 确认作废 | 善款详情。状态为已作废。备注是原内容加上这次原因。该善款不再出现在可绑定列表、「我的」里的捐赠身份和「善款」标签 |

### 3.10 把善款绑定到项目

绑定的是整笔金额，页面上不填写绑定金额。进行中、已完成、已关闭的项目都可以接收绑定。已绑定的善款不能再绑到另一个项目。

**从善款详情进入**

**操作：** 在未绑定善款详情点击「绑定到项目」。

| 取消 | 善款详情，仍是未绑定 |

**从项目详情进入**

**操作：** 在项目详情点击「绑定善款」。

**页面：选择未绑定善款**

| 可操作选项 | 操作后的页面 |
| --- | --- |

| 取消 | 项目详情，合计不变 |
| 没有可选善款 | 本页说明当前没有未绑定善款，可返回项目详情 |

**同时有两个人绑定同一笔时**

先成功的一方看到绑定完成。后到的一方停在确认页，提示该善款已绑定项目，合计不以这一次为准。后到的一方可以打开该善款详情，看到已经绑定的项目。

**解除绑定**

**操作：** 在已绑定的善款详情，或在项目详情的有效绑定记录上，点击「解除绑定」并确认。不填写原因。

**页面：原详情**

- 解除之后可以再绑到另一个项目，包括原来的项目。再绑之后，新项目的合计增加，旧项目不再包含这笔。

## 4. 未登录用户

用户端首页有三个标签。未登录时：

### 4.1 打开「项目」

**页面：「项目」标签**

「项目」高亮。页面展示：

- 项目按开始日期从新到旧排列。
- 每一行：项目名称、开始日期、状态（进行中 / 已完成 / 已关闭）、受益人人数、善款合计、开销合计、超支标记。
- 结余小于 0 的项目带「超支」。结余本身不在列表中，到项目详情才显示。
- 没有项目时，列表区说明当前没有公开项目。「善款」和「我的」仍可切换。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 按状态筛选：进行中、已完成、已关闭 | 仍是「项目」，只保留所选状态，继续按开始日期倒序。页面保留当前筛选，可清除后回到全部 |
| 清除筛选 | 「项目」，恢复默认倒序 |
| 打开某一行 | 该项目的项目详情，「项目」仍高亮 |
| 「善款」 | 「善款」标签，见 4.4 |
| 「我的」 | 「我的」的用户登录，见 4.5 |

列表上没有新建、编辑、绑定、作废。受益人只有人数，没有姓名。

### 4.2 打开项目详情

**操作：** 在「项目」中打开一条，或在「善款」中点进已绑定项目。

**页面：项目详情**

三个标签仍在。从「项目」进入时「项目」高亮；从「善款」点进项目时，进入详情后「项目」高亮，返回则回到「善款」。

页面展示：

- 项目名称、项目简介、资金用途说明、开始日期、状态、受益人人数。
- 有封面时展示封面图。没有封面时不展示封面区域。
- 善款合计、开销合计、结余。结余小于 0 时标记「超支」。
- 刚创建、尚未绑定善款也尚未登记开销时，三项金额都是 0，没有超支标记。
- 开销区：只列出未作废开销，按开销日期倒序。每条有开销日期、类别、金额、说明。没有未作废开销时，说明暂无开销。
- 项目善款明细：见 4.3。
- 进展区（P1）：只列出未撤回进展，按时间倒序。每条有日期、标题、正文、图片。没有未撤回进展时，说明暂无进展。

页面不展示：受益人姓名和唯一 ID、善款备注、平台用户 ID、身份手机号、已作废开销、已解除绑定、已撤回进展、管理操作按钮。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 返回 | 从「项目」进入的，回到「项目」列表并保留筛选；从「善款」进入的，回到「善款」 |
| 在善款明细中查看每一行 | 仍在项目详情，明细内容见 4.3 |
| 「善款」 | 「善款」标签 |
| 「我的」 | 「我的」的用户登录，见 4.5 |

### 4.3 查看项目善款明细

**页面内容（项目详情中的这一块）：**

只包含绑定到本项目、且绑定仍然有效的未作废善款，按捐款日期倒序。每一行：

- 平台（微信支付或支付宝）

- 平台

- 已绑定项目：有有效绑定时为项目名称；尚未绑定时为「尚未安排到具体项目」

未匿名时可展开个人说明。匿名行不显示对外展示名和个人说明。

没有未作废善款时，列表说明当前没有公开的捐款记录，筛选条件仍在。

页面展示：

- 手机号输入框

- 验证码输入框
- 一个提交按钮「登录」
- 说明：使用短信验证码登录，没有密码

此时还没有个人空间，也没有认领结果。捐赠身份列表、绑定捐赠身份、受益人身份和受益项目都还没有。「管理员」也不出现，要等登录后才能按手机号判断。

### 4.6 未登录用户走完公开信息的一条路径

1. 打开首页，停在「项目」，看到每个项目的名称、日期、状态、受益人人数、善款合计、开销合计和超支标记。
2. 筛选「进行中」，列表只剩进行中的项目。
3. 打开一个项目，看到简介、资金用途、封面、结余、开销和善款明细。
4. 若还没有有效绑定，善款明细显示「帮助来源待补充」。
5. 点「善款」，未绑定的行显示「尚未安排到具体项目」；已绑定的行可以点进项目。
6. 匿名捐款只显示「匿名捐款人」。未匿名捐款显示展示名或「{平台}捐款人」，并可展开个人说明。
7. 点「我的」，看到用户登录。未登录时没有「管理员」。

## 5. 登录用户

登录用户是捐款人、受益人，或两者都是。用户端不需要预先录入手机号。第一次验证通过就建立个人空间。

登录后三个标签仍在。「项目」和「善款」的公开内容见第 4 章，多出来的标记见 5.11。本章写「我的」标签。

登录成功后停在「我的」。这一页从上到下是：

| 区域 | 内容 |
| --- | --- |
| 页头 | 脱敏登录手机号、退出。登录手机号是启用管理员时，另有「管理员」 |
| 我的捐赠身份列表 | 当前手机号已认领的捐赠身份。打开一条进入该身份的捐款列表 |
| 绑定捐赠身份 | 用平台和平台用户 ID 再认领一条身份 |
| 我的受益人身份 | 尚未绑定时是姓名和唯一 ID 表单；已绑定时是自己的姓名 |
| 受益项目 | 尚未绑定受益人时说明绑定后才会列出；已绑定时进入包含自己的项目列表 |

一个登录手机号可以同时认领多条捐赠身份，并且绑定一名受益人。

### 5.1 在「我的」获取验证码并登录

**操作：** 未登录时点「我的」，输入手机号，获取验证码。

**页面：「我的」中的用户登录**

「我的」高亮。「项目」和「善款」仍可切换。这一页只有用户登录，没有「管理员」。

| 输入 | 页面要求 |
| --- | --- |
| 手机号 | 11 位中国大陆手机号 |
| 验证码 | 短信中的验证码 |

获取验证码之后：

- 发送成功：页面说明验证码已发送，5 分钟内有效。
- 同一手机号 1 小时内已经发送 5 次：本次不再发送，页面说明已达到发送上限。登录表单仍可改用此前尚未过期的验证码，或等待后再获取。
- 任意手机号都可以收到登录验证码。是否管理员不影响这次发送。

**操作：** 填写验证码并点「登录」。

| 结果 | 操作后的页面 |
| --- | --- |
| 验证码正确且未过期 | 仍在「我的」。登录表单消失，页内换成上面的四块内容，并完成本次自动认领。手机号是启用管理员时，页头出现「管理员」 |
| 验证码错误或已超过 5 分钟 | 仍停在登录表单，说明验证码不正确或已失效，可以重新获取（仍受 1 小时 5 次限制） |
| 登录态之后过期，再点「我的」 | 回到用户登录，需要重新验证。重新登录时，已经认领过的身份不会重复认领 |

第一次验证通过时建立个人空间。之后用同一手机号登录，回到原来的个人空间。

### 5.2 登录后看到「我的」

验证通过的同一时刻，系统查找「捐款身份上的手机号 = 本次登录手机号」，并且当前登录还没有认领过的身份，自动建立认领。一次登录可以认领多条。已经认领的不重复建立。

自动认领不包含这些身份：

- 身份手机号为空
- 身份手机号与本次登录手机号不同
- 当前手机号已经认领过该身份
- 身份下的善款已全部作废（这些善款本来就不会出现在捐赠身份里）

受益人不会在登录时自动绑定。「包含我」要等手动绑定姓名和唯一 ID 成功后才出现。

**页面：「我的」**

「我的」高亮。登录表单已经不在。页头是脱敏登录手机号和「退出」。登录手机号是启用管理员时，页头还有「管理员」。其下四块都在同一页。

有匹配身份时，捐赠身份列表的开头说明本次自动认领的身份数量。身份见 5.3，某一身份下的善款见 5.4。

没有匹配身份时，捐赠身份列表显示：

- 已认领身份数为 0
- 累计捐款金额、已进入项目的金额、尚未安排的金额都是 0
- 说明当前没有已认领的捐赠身份

受益人身份这时仍是绑定表单。受益项目说明：绑定受益人身份后，可以进入包含自己的项目列表。这个空状态不代替「项目」标签里的公开列表。

| 可操作选项 | 何时出现 | 操作后的页面 |
| --- | --- | --- |
| 查看捐赠身份列表 | 始终可以。没有认领时是空状态 | 仍在「我的」，内容见 5.3 |
| 绑定捐赠身份 | 始终可以。没有认领时，它是捐赠身份空状态旁的操作 | 绑定捐赠身份，见 5.5 |
| 填写受益人身份 | 尚未绑定受益人 | 仍在「我的」，表单见 5.8 |
| 查看受益项目 | 已绑定受益人 | 包含自己的项目列表，见 5.9 |
| 退出 | 始终可以 | 见 5.12 |
| 管理员 | 仅当登录手机号是启用管理员 | 工作台，见 3.1。管理端接口校验当前登录手机号 |
| 「项目」或「善款」 | 始终可以 | 对应标签，并带上第 5.11 节的标记 |

### 5.3 查看我的捐赠身份列表

**页面：「我的」中的「我的捐赠身份列表」**

这块在「我的」页上，不是另一个标签。汇总：

- 已认领身份数
- 累计捐款金额：已认领身份下全部未作废善款之和
- 已进入项目的金额：其中已有有效项目绑定的金额
- 尚未安排的金额：未绑定且未作废的金额

其下按捐款身份列出。每一条展示该身份当前的平台、公开称呼、是否匿名。这一层不展开每一笔善款。已作废善款不计入，也不单独出现。平台用户 ID 和善款备注不在本页。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 打开一条身份 | 该身份的捐款列表，见 5.4 |
| 修改对外资料 | 修改身份。修改的是这一整条身份，名下每一笔都使用保存后的资料。保存或取消后回到「我的」 |
| 解除认领 | 确认后仍在「我的」。这一身份从列表中消失，汇总重算 |
| 绑定捐赠身份 | 绑定捐赠身份，见 5.5 |
| 「项目」或「善款」 | 对应标签 |

解除认领只影响当前登录手机号。身份、其他手机号的认领、善款本身、项目绑定都还在。

若解除后一个身份都不剩，捐赠身份列表回到 5.2 的空状态，「绑定捐赠身份」仍在。

### 5.4 查看捐款列表

**操作：** 在捐赠身份列表中打开一条身份。

**页面：捐款列表**

「我的」仍高亮。页首是这条身份当前的平台、是否匿名、对外展示名、个人说明。其下每一笔未作废善款：

- 金额
- 捐款日期
- 绑定状态：未绑定或已绑定
- 项目名称：已绑定时为项目名称；未绑定时为「尚未安排到具体项目」

不展示管理备注，不展示平台用户 ID。本页没有修改对外资料、解除认领、作废和改金额。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 进入项目 | 仅已绑定的行出现。打开该项目公开详情，「项目」高亮。自己的善款行上有「我的捐款」 |
| 「尚未安排到具体项目」 | 说明文字，不能点进项目 |
| 返回「我的」 | 「我的」。捐赠身份列表、绑定入口、受益人身份和受益项目都还在 |

### 5.5 绑定捐赠身份

**页面：绑定捐赠身份**

「我的」仍高亮。页面展示两个输入项：

- 平台：微信支付或支付宝
- 平台用户 ID：去掉首尾空格后精确匹配，区分大小写，最长 64 个字符

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 查询 | 按下面三种结果之一换页，标签仍是「我的」 |
| 返回 | 「我的」 |

**结果一：找到身份，且至少有一笔未作废善款，当前手机号尚未认领**

**页面：确认绑定**

页面展示：

- 平台
- 笔数：该身份下未作废善款的笔数
- 金额合计
- 不展示平台用户 ID 以外的敏感匹配过程，不展示管理备注

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 确认绑定 | 「我的」。该身份出现在捐赠身份中，汇总重算。多个手机号可以绑定同一身份，看到的是同一条身份和同样的善款 |

**结果二：没有匹配身份，或匹配到的身份没有未作废善款**

**页面：绑定捐赠身份**

| --- | --- |

### 5.6 修改已认领身份的对外资料

**操作：** 在「我的」的捐赠身份列表里，对某一身份点击「修改对外资料」。

**页面：修改身份**

「我的」仍高亮。可以修改：

| 字段 | 页面上的约束 |
| --- | --- |
| 是否匿名 | 是或否 |
| 对外展示名 | 可空。未匿名时，公开页面用它作为称呼；为空时公开页面用「{平台}捐款人」 |
| 个人说明 | 可空，不超过 200 字。未匿名时公开 |
| 手机号 | 可以改成另一个 11 位中国大陆手机号，也可以清空 |

平台和平台用户 ID 显示为不可修改的文字。

保存上述任意一项后，这条身份变为「用户已修改」，并记下修改时间。手机号和对外展示名共用这一个标记。多个登录手机号认领同一身份时，任意一个手机号保存都会加上标记。标记加上之后一直保持。之后仍可继续修改内容。管理人员之后的录入和导入不再覆盖这四项：是否匿名、对外展示名、个人说明、手机号。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 保存 | 回到「我的」。捐赠身份列表里这条身份已是新内容 |
| 取消 | 回到「我的」，资料不变 |

保存手机号时的后续结果，在保存成功页用文字说明：

- 改成一个新的 11 位手机号：旧的认领都保留，包括正在修改的这个用户。新号码如果已经有登录身份，会立刻补上认领；还没有人用该号码登录过，则等该号码下次登录时自动认领。
- 清空手机号：保存成功。之后新的登录不会再因为这个号码自动认领该身份。已经存在的认领保留。
- 手机号不是 11 位中国大陆号码：停在修改身份，说明格式不正确，不保存。
- 个人说明超过 200 字：停在修改身份，说明超出长度，不保存。

### 5.7 解除认领

**操作：** 在捐赠身份列表的某一身份上点击「解除认领」，并确认。

**页面：「我的」**

- 当前手机号的捐赠身份里不再显示该身份及其善款。
- 汇总按剩下的认领重算。
- 另一个已经认领同一身份的手机号，打开「我的」后仍然看得到这些善款。
- 「善款」标签里，这些未作废善款仍在。项目上的有效绑定仍在。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 再次绑定同一身份 | 确认绑定页，确认后该身份重新出现在捐赠身份中 |
| 继续查看其他已认领身份 | 仍在「我的」 |

### 5.8 查看并绑定我的受益人身份

**操作：** 在「我的」查看「我的受益人身份」。尚未绑定时，这块就是绑定表单。

**页面：「我的」中的「我的受益人身份」**

| 字段 | 要求 |
| --- | --- |
| 姓名 | 必填，去掉首尾空格后与档案一致 |
| 唯一 ID | 必填，去掉首尾空格后与档案一致。推荐填写身份证号 |

不一致或档案不存在时，都提示「未找到匹配的受益人信息」，不说明是姓名不对还是唯一 ID 不对，也不建立绑定。受益项目仍显示绑定后才会列出，不能进入项目列表。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 提交绑定 | 成功则同一页变为 5.9；失败则停在「我的」，受益人身份处显示「未找到匹配的受益人信息」 |
| 「项目」 | 「项目」列表。受益人这块的空状态不代替公开项目 |
| 「善款」 | 「善款」标签 |

### 5.9 绑定成功后查看受益人身份和受益项目

**操作：** 姓名和唯一 ID 与档案一致，在「我的」提交绑定。

**页面：「我的」**

受益人身份和受益项目两块同时更新：

- 我的受益人身份：当前绑定的受益人姓名。只显示自己的姓名，不显示其他受益人，不显示唯一 ID。
- 受益项目：进入包含自己的项目列表。列表按开始日期倒序。每一行是项目名称、开始日期、项目简介。
- 没有此类项目时，项目列表说明「暂时没有包含我的项目」。「项目」标签里的公开列表仍可查看。

一名受益人可以在多个项目里。受益人尚未登录时，管理人员先把档案加入项目也有效；绑定成功后，项目列表立刻列出这些项目。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 打开受益项目 | 项目列表，「我的」仍高亮 |
| 在项目列表中打开一条 | 项目公开详情，「项目」高亮，页上有「包含我」，见 5.10 |
| 从项目列表返回 | 「我的」 |
| 解除受益人绑定 | 确认后「我的」回到 5.8 的绑定表单。该手机号不再显示「包含我」，受益项目回到未绑定说明，不能再进入这份项目列表。档案、项目，以及其他手机号上的绑定都保留 |
| 「项目」 | 全部公开项目的列表。自己所在的项目打开后带「包含我」 |
| 「善款」 | 「善款」标签 |

一个手机号同时只能绑定一个受益人档案。已绑定后，受益人身份处没有第二份绑定表单。要换成另一名受益人，先解除，再提交另一组姓名和唯一 ID。

两个手机号可以绑定同一个档案。两边的「我的」都看得到同一批受益项目，也都看不到对方或其他受益人的姓名。

### 5.10 打开包含自己的项目

**操作：** 从受益项目的项目列表，或从「项目」打开自己所在的项目。

**页面：项目详情**

「项目」高亮。公开内容与第 4.2、4.3 节相同，并额外显示「包含我」。

仍然看不到：其他受益人姓名、唯一 ID、受益人备注、善款备注、平台用户 ID、身份手机号。

若这个项目里也有当前手机号认领过的善款，善款明细里那些行同时带「我的捐款」。

| 可操作选项 | 操作后的页面 |
| --- | --- |
| 返回 | 从受益项目的项目列表进入的，回到该列表；从「项目」进入的，回到「项目」列表 |
| 「善款」 | 「善款」标签 |
| 「我的」 | 「我的」 |

### 5.11 登录后再次浏览「项目」和「善款」

登录不改变公开字段，只在原有内容上增加标记。包含自己的项目列表从「我的」的受益项目进入，不在「项目」标签上再做一层筛选。

**「项目」**

- 列表字段与未登录时相同。
- 打开自己所在的项目后，详情显示「包含我」。
- 不在这个项目中时，详情不显示「包含我」。

**项目善款明细**

- 某一行属于当前手机号已认领的捐赠身份：该行显示「我的捐款」。
- 其他行与未登录时相同。

**「善款」**

- 字段与未登录时相同，仍按公开称呼展示。
- 查看自己的金额、匿名状态、展示名和个人说明，回到「我的」的捐赠身份列表，再进入该身份的捐款列表。

### 5.12 退出登录

**操作：** 在「我的」页头点击「退出」。

**页面：「项目」**

页头在退出前展示当前登录手机号的脱敏值（前 3 位和后 4 位）。退出后：

- 回到首页「项目」，恢复为未登录状态。
- 再点「我的」，看到 4.5 的用户登录。未登录时没有「管理员」。
- 「项目」和「善款」仍可查看。
- 认领和受益人绑定都还在，下次用同一手机号登录后会再出现在「我的」。

### 5.13 同一个人既捐款又受助

**操作：** 用同一个手机号在「我的」完成登录。

登录成功后，「我的」同一页上有两件独立的事：

1. 捐赠身份由自动认领处理。没有匹配手机号时，使用 5.5 绑定捐赠身份。
2. 受益人身份仍是绑定表单，直到按 5.8 绑定成功。受益项目在绑定成功后才进入项目列表。

两件事可以只做一件。只认领捐赠身份时，项目善款明细上有「我的捐款」，项目详情没有「包含我」。只绑定受益人时，项目详情有「包含我」，捐赠身份仍是空状态和「绑定捐赠身份」。

## 6. 跨角色串联

下面三条路径把三种角色连在一起。每一步都对应前面的页面。

### 6.1 录入、认领、绑定到项目

1. 技术人员已在数据库中放好至少一名启用管理员。
2. 管理员打开用户端「我的」，用预先录入的手机号完成用户登录。页头出现「管理员」。点击后直接进入工作台。未绑定善款为 0，进行中项目为 0，超支项目为 0。
3. 管理员打开受益人列表，新建受益人，填写姓名、唯一 ID、备注，进入受益人详情。
4. 在受益人详情点击「创建项目」。该受益人已选中且不能取消。填写名称、简介、资金用途、开始日期后保存。项目详情为进行中，三项金额为 0。
5. 未登录用户打开首页「项目」，能看到这个项目，受益人只有人数，善款明细为「帮助来源待补充」。
6. 管理员单笔录入一笔微信支付善款，匿名默认为「是」。身份尚不存在，保存后进入善款详情，状态未绑定。
7. 未登录用户点「善款」，看到这条记录，称呼为「匿名捐款人」，项目列为「尚未安排到具体项目」。
8. 知道平台和平台用户 ID 的捐款人，点「我的」，用自己的手机号登录。若录入时没有手机号，捐赠身份为空，页上有「绑定捐赠身份」。
9. 捐款人填写平台和平台用户 ID，确认页显示笔数和金额合计。确认后仍在「我的」，捐赠身份列表里出现该身份。打开后，捐款列表里这笔的状态为未绑定。
10. 另一个手机号按同样步骤绑定同一身份，也能看到同一笔。先绑定的手机号仍然看得到。
11. 管理员从善款详情把这笔绑定到刚创建的项目。善款详情变为已绑定。项目善款合计等于这笔全额，结余同步增加。
12. 未登录用户重新打开项目详情，善款明细出现这条匿名捐款，「帮助来源待补充」消失。
13. 捐款人打开「我的」，再打开该身份的捐款列表，这笔的项目列变成项目名称；进入项目后，自己的那一行带「我的捐款」。

### 6.2 覆盖展示资料，以及用户修改后不再覆盖

1. 管理员第一次单笔录入某平台用户，匿名为「是」。善款详情中身份为匿名，用户已修改为否。
2. 管理员再次单笔录入同一平台和同一平台用户 ID，改为不匿名，展示名「张三」，个人说明「希望用于助学」。保存前页面说明本次会覆盖三项。
3. 保存后新增第二笔未绑定善款。身份详情里匿名为否、展示名为张三、说明为「希望用于助学」，标记仍是用户未修改。公开称呼变为「张三」，可展开个人说明。两笔善款都使用这套当前资料。
4. 捐款人认领后，在修改身份里把展示名改成「张先生」并保存。身份变为用户已修改。
5. 管理员再次录入或导入这个身份。保存前或预览中标明展示名和手机号本次不覆盖。写入后只多一笔善款，公开称呼仍是「张先生」。
6. 捐款人把身份手机号改成一个新的 11 位号码。旧手机号的认领还在。新号码若已登录，「我的」的捐赠身份立刻多出该身份；若尚未登录，下次登录时自动出现。
7. 捐款人若清空手机号并保存，之后新的登录不会再靠这个空号码自动认领。已有认领保留。

### 6.3 导入两个平台、项目结余和受益人

1. 管理员按模板准备两行：一行微信支付、一行支付宝，手机号都填同一个 11 位号码，金额和日期合法。导入预览标明将新建两个身份，手机号将写入。确认写入。
2. 该手机号在「我的」登录后，捐赠身份列表里同时出现两个身份。各自的捐款列表里是对应的未作废善款。
3. 若另一行手机号留空，该身份不会因为同批其他行而自动认领。手机号格式错误时，预览标出该行行号和原因，整批都不写入。
4. 管理员把两笔都绑定到项目 A。再试图把其中一笔绑到项目 B 时，页面提示该善款已绑定项目。
5. 管理员解除其中一笔。项目 A 的善款合计减少。再把这笔绑到项目 B，B 的合计增加，A 不再包含它。已完成、已关闭的项目同样可以完成这次绑定。
6. 管理员在项目上登记一笔大于结余的开销。保存成功，详情标记「超支」。工作台的超支项目数包含它。「项目」标签的列表也带超支标记。
7. 受益人用手机号在「我的」登录。受益人身份先是绑定表单。提交与档案一致的姓名和唯一 ID 后，从受益项目进入项目列表，列出项目名称、开始日期和简介。打开项目后显示「包含我」，看不到其他受益人。
8. 该手机号在未解除前不能再绑定第二名受益人。另一个手机号可以绑定同一档案，并在自己的「我的」里看到同一批受益项目。
9. 新手机号没有任何捐赠身份、也还没绑定受益人时，在「我的」登录：捐赠身份给出「绑定捐赠身份」，受益人身份给出绑定表单。切到「项目」仍可浏览全部公开项目。
